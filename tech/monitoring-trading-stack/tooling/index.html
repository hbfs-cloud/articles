Pourquoi le tooling est si important

Revenons un instant sur les lecons de la Partie 1 :

  • Knight Capital a perdu 440 millions de dollars en 45 minutes parce qu'il n'y avait pas de kill-switch automatique. Un simple bot Discord avec !kill aurait pu couper les pertes.
  • Archegos Capital a explose parce que personne ne surveillait l'exposition concentree. Un dashboard Grafana avec une alerte "exposition > 30% sur un seul titre" aurait leve un drapeau rouge.
  • Three Arrows Capital n'avait aucune visibilite sur sa liquidite. Un panel Prometheus mesurant le ratio margin call aurait sonne l'alarme des semaines avant la faillite.

Le monitoring ne remplace pas une bonne strategie. Mais une bonne strategie sans monitoring est comme une voiture de course sans frein : elle ira tres vite... droit dans le mur.

Open Source vs Commercial : le vrai debat

Beaucoup de traders debutants hesitent entre des solutions commerciales (TradingView alerts, Datadog, CloudWatch) et des outils open source. Voici la regle simple :

Commercial = rapide a mettre en place, limite en personnalisation, cout recurrent. Parfait si vous tradez manuellement et avez besoin d'alertes basiques sur les prix.

Open Source = plus de setup initial (un weekend), personnalisation infinie, cout quasi nul. Indispensable si vous faites du trading algorithmique et avez besoin de metriques custom (drawdown, latence, exposition, slippage...).

Notre recommandation : commencez par l'open source des le debut. L'investissement en temps initial vous fera economiser des milliers d'euros sur le long terme et vous donnera un controle total sur votre infrastructure.

Grafana : Le Tableau de Bord Universel

Grafana est le standard de facto pour la visualisation de donnees en temps reel. Cree en 2014 par Torkel Odegaard, il est utilise par Netflix, Uber, Bloomberg et des milliers d'equipes de trading dans le monde. Et il est 100% open source (licence AGPLv3).

Pour un trader, Grafana est l'equivalent de votre cockpit d'avion : c'est l'ecran unique ou vous voyez tout ce qui se passe dans votre stack, en un coup d'oeil. P&L en temps reel, positions ouvertes, drawdown, latence des ordres, sante du systeme.

Pourquoi Grafana et pas TradingView ?

Question frequente et legitime. TradingView est excellent pour l'analyse technique des graphiques de prix. Grafana est concu pour un usage completement different :

Critere TradingView Grafana
Metriques custom Non (Pine Script limite aux prix) Oui (n'importe quelle metrique imaginable)
Donnees systeme Non CPU, RAM, latence, erreurs, uptime
P&L temps reel Non (pas de connexion broker native) Oui (via Prometheus + API broker)
Alertes flexibles Limitees (prix, volume, indicateurs) Illimitees (PromQL, multi-condition, templated)
Cout 30 USD/mois (Essential) 0 EUR (self-hosted)
Self-hosted Non (SaaS uniquement) Oui (Docker, binaire, Kubernetes)
Multi-datasource Donnees TradingView uniquement 100+ data sources (Prometheus, SQL, APIs, etc.)

En resume : TradingView pour analyser les marches, Grafana pour monitorer votre stack. Les deux sont complementaires.

Installation avec Docker Compose

La facon la plus simple d'installer Grafana est via Docker. Voici le fichier docker-compose.yml minimal :

# docker-compose.grafana.yml
version: '3.8'

services:
  grafana:
    image: grafana/grafana:latest
    container_name: trading-grafana
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_USER=trader
      - GF_SECURITY_ADMIN_PASSWORD=changeme_strong_password
      - GF_USERS_ALLOW_SIGN_UP=false
      - GF_SERVER_ROOT_URL=http://localhost:3000
      - GF_INSTALL_PLUGINS=grafana-clock-panel,grafana-piechart-panel
    volumes:
      - grafana-data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning
    networks:
      - trading-net

volumes:
  grafana-data:

networks:
  trading-net:
    driver: bridge

Lancez avec docker compose -f docker-compose.grafana.yml up -d puis ouvrez http://localhost:3000. Votre dashboard est pret en 30 secondes.

Les 4 dashboards essentiels du trader

Apres des mois d'iteration, nous avons identifie les 4 dashboards qui couvrent 95% des besoins d'un trader systematique :

Dashboard 1 : P&L Tracker
P&L cumule (realise + unrealise), par strategie et par instrument. Courbe d'equity. Drawdown en cours. Comparaison vs benchmark (SPY).
Dashboard 2 : Positions Monitor
Positions ouvertes en temps reel. Exposition nette (long - short). Delta portfolio. Beta-weighted exposure. Heatmap par secteur.
Dashboard 3 : Risk Metrics
VaR (95%, 99%). Max drawdown rolling 30j. Sharpe ratio. Win rate par strategie. Limites et violations.
Dashboard 4 : System Health
Latence API broker (p50, p99). CPU/RAM. Files de messages. Erreurs par endpoint. Uptime de chaque service.

Provisioning automatique

Pour que Grafana charge automatiquement vos dashboards et data sources au demarrage, creez cette structure :

grafana/
  provisioning/
    datasources/
      prometheus.yml      # Connexion a Prometheus
      postgres.yml        # Connexion a PostgreSQL
    dashboards/
      provider.yml        # Ou trouver les dashboards JSON
      trading-pnl.json    # Dashboard P&L
      positions.json      # Dashboard positions
      risk.json           # Dashboard risques
      system.json         # Dashboard systeme

Le fichier provider.yml :

# grafana/provisioning/dashboards/provider.yml
apiVersion: 1
providers:
  - name: 'Trading Dashboards'
    orgId: 1
    folder: 'Trading'
    type: file
    disableDeletion: false
    editable: true
    updateIntervalSeconds: 30
    options:
      path: /etc/grafana/provisioning/dashboards
      foldersFromFilesStructure: false

Et le fichier de data source pour Prometheus :

# grafana/provisioning/datasources/prometheus.yml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: true
    jsonData:
      timeInterval: '15s'
      httpMethod: POST

Conseil pratique : commencez simple

Ne creez pas 20 dashboards le premier jour. Commencez par le P&L Tracker uniquement. Ajoutez un dashboard par semaine en fonction de vos besoins reels. Un dashboard que personne ne regarde est un dashboard inutile.

La regle d'or : si vous ne pouvez pas expliquer en une phrase pourquoi un panel existe, supprimez-le.

Variables et templates Grafana

La fonctionnalite la plus puissante de Grafana pour un trader est les variables de template. Elles permettent de creer un seul dashboard adaptatif :

# Exemples de variables utiles dans Grafana

# Variable $strategy : selectionner la strategie
# Type: Query | Source: Prometheus
# Query: label_values(trading_pnl_realized_total, strategy)
# Multi-value: Yes | Include All: Yes

# Variable $timerange : periode d'analyse
# Type: Custom
# Values: 1h, 6h, 1d, 7d, 30d, 90d

# Utilisation dans les requetes PromQL :
sum(trading_pnl_realized_total{strategy=~"$strategy"})
rate(trading_orders_total{strategy=~"$strategy"}[$timerange])

Avec les variables, un seul dashboard P&L peut afficher les resultats de toutes vos strategies ou d'une seule, sur n'importe quelle periode. Un gain de temps enorme.

Prometheus + Alertmanager : Metriques et Alertes

Prometheus est le moteur qui alimente Grafana. Cree par SoundCloud en 2012, devenu projet CNCF, c'est le standard pour la collecte de metriques dans les architectures modernes.

Son modele est simple : Prometheus scrape (interroge) vos services a intervalles reguliers. Pas besoin d'envoyer des donnees a Prometheus, c'est lui qui vient les chercher. C'est le modele "pull".

Exposer les metriques en Python

# pip install prometheus_client
# metrics.py

from prometheus_client import (
    Counter, Gauge, Histogram,
    start_http_server, CollectorRegistry
)

registry = CollectorRegistry()

# Metriques P0
pnl_realized = Counter(
    'trading_pnl_realized_total', 'P&L realise cumule',
    ['strategy'], registry=registry
)
pnl_unrealized = Gauge(
    'trading_pnl_unrealized_total', 'P&L non realise',
    ['strategy'], registry=registry
)
drawdown = Gauge(
    'trading_drawdown_current_percent', 'Drawdown actuel %',
    registry=registry
)
positions_count = Gauge(
    'trading_positions_count', 'Positions ouvertes',
    ['strategy'], registry=registry
)

# Metriques P1
exposure = Gauge(
    'trading_exposure_usd', 'Exposition USD',
    ['direction'], registry=registry
)
order_latency = Histogram(
    'trading_order_latency_seconds', 'Latence ordres',
    buckets=[0.01, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0],
    registry=registry
)
api_errors = Counter(
    'trading_api_errors_total', 'Erreurs API',
    ['endpoint'], registry=registry
)

def start_metrics_server(port=8000):
    start_http_server(port, registry=registry)
    print(f"Metriques sur http://0.0.0.0:{port}/metrics")

def on_trade(strategy, pnl, latency_s):
    pnl_realized.labels(strategy=strategy).inc(max(0, pnl))
    order_latency.observe(latency_s)

def update_positions(strategy, count, unrealized):
    positions_count.labels(strategy=strategy).set(count)
    pnl_unrealized.labels(strategy=strategy).set(unrealized)

Regles d'alertes

# rules/trading_alerts.yml
groups:
  - name: trading_critical
    rules:
      - alert: DrawdownCritical
        expr: trading_drawdown_current_percent > 10
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "DRAWDOWN {{ $value | printf \"%.1f\" }}%"

      - alert: DailyLossExceeded
        expr: sum(increase(trading_pnl_realized_total[1d])) < -5000
        for: 0m
        labels:
          severity: critical
        annotations:
          summary: "PERTE JOUR > 5000 USD"

      - alert: TradingBotDown
        expr: up{job="trading-bot"} == 0
        for: 30s
        labels:
          severity: critical
        annotations:
          summary: "Bot de trading DOWN"

      - alert: TooManyPositions
        expr: sum(trading_positions_count) > 20
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "{{ $value }} positions (max 20)"

  - name: trading_operations
    rules:
      - alert: HighOrderLatency
        expr: histogram_quantile(0.99, rate(trading_order_latency_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Latence p99 > 2s"

      - alert: APIErrorRate
        expr: rate(trading_api_errors_total[5m]) > 0.1
        for: 3m
        labels:
          severity: warning
        annotations:
          summary: "Erreurs API {{ $value | printf \"%.2f\" }}/s"

La fatigue d'alertes tue le monitoring

Le piege numero 1 est de creer trop d'alertes. Si vous recevez 50 notifications par jour, vous les ignorerez toutes, y compris les critiques. Regle : 3 alertes max par jour en conditions normales.

Webhook vs Bot Discord

Webhook = tuyau unidirectionnel. Vous envoyez un message via une URL. Parfait pour les notifications automatiques (alertes Prometheus).

Bot = programme connecte en permanence qui lit les messages et reagit aux commandes. Plus complexe mais interactif (kill-switch, status).

Recommandation : webhooks pour les alertes, bot pour les commandes interactives.

Envoyer des alertes via Webhook

# discord_alerts.py
import requests
from datetime import datetime

WEBHOOK_CRITICAL = "https://discord.com/api/webhooks/YOUR_ID/YOUR_TOKEN"
WEBHOOK_TRADES = "https://discord.com/api/webhooks/YOUR_ID2/YOUR_TOKEN2"

def send_embed(webhook_url, title, description, color=0xFF0000, fields=None):
    """Envoie un embed Discord formate."""
    embed = {
        "title": title,
        "description": description,
        "color": color,
        "timestamp": datetime.utcnow().isoformat(),
        "footer": {"text": "Trading Bot Monitor"},
    }
    if fields:
        embed["fields"] = fields
    resp = requests.post(webhook_url, json={"embeds": [embed]})
    return resp.status_code == 204

def alert_drawdown(current_dd, max_dd, pos_count):
    send_embed(
        WEBHOOK_CRITICAL,
        title="DRAWDOWN CRITIQUE",
        description=f"Drawdown : **{current_dd:.1f}%** (max : {max_dd}%)",
        color=0xFF0000,
        fields=[
            {"name": "Positions", "value": str(pos_count), "inline": True},
            {"name": "Action", "value": "Reduire exposition", "inline": True},
        ]
    )

def alert_trade(symbol, side, qty, price, pnl=None):
    color = 0x00FF00 if side == "BUY" else 0xFF6600
    desc = f"**{side}** {qty} x {symbol} @ ${price:.2f}"
    if pnl is not None:
        desc += f"\nP&L: **${pnl:+.2f}**"
    send_embed(WEBHOOK_TRADES, f"Trade : {symbol}", desc, color)

def daily_report(pnl_today, pnl_total, win_rate, trades, dd):
    color = 0x00FF00 if pnl_today >= 0 else 0xFF0000
    sign = "+" if pnl_today >= 0 else ""
    send_embed(
        WEBHOOK_TRADES,
        title="Resume Quotidien",
        description=f"P&L jour : **{sign}${pnl_today:.2f}**",
        color=color,
        fields=[
            {"name": "P&L Total", "value": f"${pnl_total:.2f}", "inline": True},
            {"name": "Win Rate", "value": f"{win_rate:.1f}%", "inline": True},
            {"name": "Trades", "value": str(trades), "inline": True},
            {"name": "Drawdown", "value": f"{dd:.1f}%", "inline": True},
        ]
    )

Bot interactif avec kill-switch

# discord_bot.py
import discord
from discord.ext import commands
import asyncio

bot = commands.Bot(command_prefix='!', intents=discord.Intents.default())

@bot.command()
async def status(ctx):
    """Etat actuel du bot de trading."""
    state = get_trading_state()  # Votre fonction
    emoji = "ACTIF" if state["active"] else "ARRETE"
    embed = discord.Embed(
        title=f"Status : {emoji}",
        color=0x00FF00 if state["active"] else 0xFF0000
    )
    embed.add_field(name="Positions", value=str(state["positions"]), inline=True)
    embed.add_field(name="P&L Jour", value=f"${state['pnl']:.2f}", inline=True)
    embed.add_field(name="Drawdown", value=f"{state['dd']:.1f}%", inline=True)
    await ctx.send(embed=embed)

@bot.command()
async def positions(ctx):
    """Liste les positions ouvertes."""
    pos_list = get_open_positions()
    if not pos_list:
        await ctx.send("Aucune position ouverte.")
        return
    embed = discord.Embed(title="Positions Ouvertes", color=0x3498DB)
    for p in pos_list:
        embed.add_field(
            name=f"{p['symbol']} ({p['side']})",
            value=f"Qty: {p['qty']} | Entry: ${p['entry']:.2f} | P&L: ${p['pnl']:+.2f}",
            inline=False
        )
    await ctx.send(embed=embed)

@bot.command()
async def kill(ctx):
    """KILL SWITCH - Ferme tout et arrete le bot."""
    if not ctx.author.guild_permissions.administrator:
        await ctx.send("Acces refuse. Admin requis.")
        return
    await ctx.send("**KILL SWITCH** : Tapez `CONFIRM` dans 10 secondes.")
    try:
        await bot.wait_for(
            'message',
            check=lambda m: m.author == ctx.author and m.content == "CONFIRM",
            timeout=10.0
        )
    except asyncio.TimeoutError:
        await ctx.send("Kill switch annule (timeout).")
        return
    result = execute_kill_switch()
    await ctx.send(f"KILL SWITCH ACTIVE. {result['closed']} positions fermees.")

@bot.command()
async def pause(ctx):
    set_trading_active(False)
    await ctx.send("Bot en PAUSE.")

@bot.command()
async def resume(ctx):
    set_trading_active(True)
    await ctx.send("Bot REACTIVE.")

bot.run("YOUR_DISCORD_BOT_TOKEN")

Securite du kill-switch

Le kill-switch Discord est un dernier recours. Implementez aussi : un kill-switch local (fichier KILL), un circuit-breaker automatique (3 pertes = pause 1h), et des limites hard-codees (drawdown max, perte max).

Claude Code : L'Assistant IA pour le Monitoring

Claude Code est l'agent de codage d'Anthropic, executable dans votre terminal. Via le Model Context Protocol (MCP), il accede a vos donnees de marche, bases de donnees, metriques et fichiers en temps reel.

MCP explique simplement

Imaginez que Claude est un analyste brillant enferme dans une piece sans fenetre. MCP ouvre des fenetres :

  • MCP Market Data : prix temps reel, indicateurs techniques, sentiment
  • MCP PostgreSQL : historique de trades, positions, audit trail
  • MCP Prometheus : metriques de monitoring (P&L, latence)
  • MCP Filesystem : logs, configuration, code source

Avec MCP, Claude Code interroge toutes ces sources depuis une seule interface. C'est comme donner a votre analyste un Bloomberg Terminal + acces admin + connexion DB, le tout simultanement.

Cas d'usage concrets

Ce qu'il ne faut PAS automatiser avec l'IA

  • Execution d'ordres : l'IA suggere, le code deterministe execute
  • Risk management : regles hard-codees, pas interpretees par un LLM
  • Kill-switch : 100% deterministe (if drawdown > X then stop)
  • Sizing : formules mathematiques (Kelly, vol targeting), pas du "feeling" IA

L'IA analyse et suggere, le code deterministe execute et protege.

OpenClow : L'Orchestrateur Open Source

OpenClow est un orchestrateur de trading open source concu pour les traders retail. C'est le "systeme nerveux central" qui coordonne Grafana, Prometheus, Discord et Claude Code dans un flux coherent.

Les 4 modules

Scheduler
Planifie les strategies : cron, evenements marche (open/close), triggers custom (earnings, FOMC).
Executor
Execute les ordres via APIs broker (IBKR, Alpaca, Binance) avec retry et audit trail.
Risk Manager
Valide chaque ordre contre les limites (max position, drawdown, exposition) avant execution.
Monitor
Expose metriques Prometheus, envoie alertes Discord, genere rapports quotidiens.

Configuration

# openclow.yml
version: "1.0"

broker:
  provider: alpaca
  api_key: ${ALPACA_KEY}
  api_secret: ${ALPACA_SECRET}
  paper: true

strategies:
  momentum_etf:
    enabled: true
    module: strategies.momentum_etf
    schedule: "0 9 31 * * 1-5"
    universe: ["SPY", "QQQ", "IWM", "EFA", "EEM", "GLD", "TLT"]
    params:
      lookback_days: 20
      top_n: 3

  mean_reversion:
    enabled: true
    module: strategies.mean_reversion
    schedule: "*/5 9-16 * * 1-5"
    universe: ["AAPL", "MSFT", "GOOGL", "AMZN", "NVDA"]
    params:
      zscore_entry: 2.0
      zscore_exit: 0.5

risk:
  max_portfolio_drawdown: 10
  max_daily_loss: 5000
  max_position_size: 10
  max_positions: 15
  max_sector_exposure: 30
  circuit_breaker:
    enabled: true
    trigger: 3
    cooldown_minutes: 60

monitoring:
  prometheus:
    enabled: true
    port: 8000
  discord:
    enabled: true

Securite en production

  • Changez TOUS les mots de passe par defaut
  • N'exposez PAS Prometheus (9090) et PostgreSQL (5432) sur Internet

Les 3 takeaways de cette serie

1. Le monitoring n'est pas optionnel. Chaque dollar investi en monitoring sauve potentiellement des milliers en pertes evitables. Les post-mortems de la Partie 1 le prouvent.

2. L'architecture avant les outils. Comprenez les 4 couches de la Partie 2 avant de choisir vos outils. Un bon design avec des outils moyens bat toujours des outils excellents sans design.

3. Commencez simple, iterez vite. Prometheus + Grafana + webhook Discord suffisent pour demarrer. Ajoutez de la complexite uniquement quand c'est necessaire.
