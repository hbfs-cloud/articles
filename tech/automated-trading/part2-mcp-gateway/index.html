MCP Protocol Fundamentals

The Model Context Protocol (MCP) is an open standard created by Anthropic that lets AI models interact with external tools and data sources through a unified interface. Think of it as a USB-C port for AI — one standardized connection that works with any compatible service.

How MCP Works

The architecture follows a client-server model:

  1. MCP Client (Claude Code) discovers available tools by querying the MCP server
  2. MCP Server (DailyTickers Gateway) exposes a catalog of tools with JSON Schema definitions
  3. Claude Code calls tools by name with typed parameters
  4. The server executes the request and returns structured results
  5. Claude Code processes the results and can chain additional tool calls

Configuration

MCP servers are declared in your Claude Code settings. The DailyTickers Gateway connects via stdio transport:

~/.claude/settings.json
{
  "mcpServers": {
    "dailytickers": {

Strategy-Specific Screeners

Oversold Bounce
rsi14 < 30 && vol > sma(vol,20) * 2 && close > sma(close,200) && macdHist > 0

What it finds:

Stocks that are oversold (RSI below 30) with volume confirmation (2x average), still in a long-term uptrend (above 200-day SMA), and showing early momentum reversal (MACD histogram turning positive). These are high-probability mean reversion setups.

Momentum Breakout
close > max(high, 20d) && vol > avgVol * 1.5 && rsi14 > 55 && rsi14 < 75 && close > ema(close,50)

What it finds:

Stocks breaking out above their 20-day high on above-average volume, with RSI in the sweet spot (strong but not overbought), and above the 50 EMA. These are continuation setups with momentum confirmation.

Volatility Squeeze
bbWidth < 5 && atr14 < sma(atr14,20) * 0.7 && vol < avgVol * 0.6 && close > sma(close,200)

What it finds:

Stocks in a tight consolidation (narrow Bollinger Bands, low ATR, low volume) above the 200 SMA. These often precede explosive moves. The direction of the breakout determines the trade.

Trend Following
close > ema(close,20) && ema(close,20) > ema(close,50) && ema(close,50) > ema(close,200) && rsi14 > 50 && change(close,5d) > 0
Safe Haven (Risk-Off)
sector == "Utilities" || sector == "Consumer Staples" || symbol IN ("GLD","SLV","TLT","SH","SQQQ") && rsi14 < 65 && change(close,5d) > 0
Value + Insider Buying
pe < 15 && forwardPE < pe && change(close,3m) < -15 && insider_net_buying_90d > 0

Regime Detection Algorithm

The AutoScreener uses a composite of 7 indicators to determine the regime:

Regime Detection Logic (Pseudocode)
function detectRegime(marketData) {
  const signals = {
    vix:         marketData.vix,                    // VIX level
    vixTrend:    marketData.vix_5d_change,          // VIX direction
    breadth:     marketData.advanceDeclineRatio,     // NYSE A/D ratio
    putCall:     marketData.putCallRatio,            // Options P/C ratio
    spyRsi:      marketData.spy_rsi14,              // SPY RSI
    dxy:         marketData.dxy_5d_change,          // Dollar strength
    yieldCurve:  marketData.us10y - marketData.us2y // Yield spread
  };

  let score = 0; // -100 (full risk-off) to +100 (full risk-on)

  // VIX contribution (weight: 25%)
  if (signals.vix < 16) score += 25;
  else if (signals.vix < 22) score += 10;
  else if (signals.vix < 30) score -= 15;
  else score -= 25;

  // VIX trend (weight: 10%)
  if (signals.vixTrend < -2) score += 10;  // VIX falling = bullish
  else if (signals.vixTrend > 3) score -= 10;

  // Breadth (weight: 25%)
  if (signals.breadth > 2.0) score += 25;
  else if (signals.breadth > 1.0) score += 10;
  else if (signals.breadth < 0.5) score -= 25;
  else score -= 10;

  // Put/Call (weight: 15%)
  if (signals.putCall > 1.2) score -= 15;   // Fear = bearish
  else if (signals.putCall < 0.7) score += 15;

  // SPY RSI (weight: 10%)
  if (signals.spyRsi > 65) score += 10;
  else if (signals.spyRsi < 35) score -= 10;

  // Dollar (weight: 10%)
  if (signals.dxy > 1.5) score -= 10;  // Strong dollar = risk-off
  else if (signals.dxy < -1.0) score += 10;

  // Yield curve (weight: 5%)
  if (signals.yieldCurve < 0) score -= 5; // Inverted = warning
  else score += 5;

  // Map score to regime
  if (score > 40) return "RISK_ON";
  if (score > 10) return "NEUTRAL";
  if (score > -20) return "EARLY_RISK_OFF";
  if (score <= -20) {
    if (signals.vixTrend < -3) return "RECOVERY";
    return "RISK_OFF";
  }
}

Why Auto-Adaptive Matters

A momentum breakout strategy that works beautifully in a bull market can lose money fast in a risk-off environment. The AutoScreener prevents this by automatically shifting to defensive strategies when conditions deteriorate. During the March 2026 early risk-off environment (VIX 23.75), it allocated 30% to oversold bounce and 20% to safe haven — exactly the right response.

# Final Selection — Top 10 A+ Setups

## Selection Criteria
From scored candidates:
1. Composite score >= 85 (A+ threshold)
2. No layer below 60 (no red flags)
3. Technical confluence >= 3 signals
4. Diversification: min 5 US + 2 EU + 1 APAC + 2 ETF

## In Risk-Off/Early Risk-Off regimes:
- Minimum 20% defensive setups (GLD, TLT, SH, SQQQ, safe-haven ETFs)

- Entry zone: current price or key level (support, EMA pullback)

- TP2: second resistance or +2R

- Highest composite score
- Highest technical confluence
- Best R/R ratio
- Most unique (not in recent scans)

Data Quality & Gotchas

Rate Limits

The Gateway handles rate limiting internally, but here are practical guidelines:

  • QueryData: Max 50 symbols per call, unlimited calls per minute
  • GetInstruments: 1 symbol at a time, ~2-5 seconds per call
  • RunScreener: Max 5 concurrent screens, ~3-8 seconds each
  • RunAutoScreener: 1 call at a time, ~10-15 seconds

Common Pitfalls

Pitfall: Stale Entry Prices

If the scanner runs at 23:00 but uses closing data from 16:00, after-hours moves can invalidate setups. Always validate entry prices against current quote before posting alerts. Reject if >10% drift.

Pitfall: Missing Data for Foreign Stocks

EU/APAC stocks traded as ADRs (e.g., SAP, ASML) have full data. But ETFs like EWG or FXI may lack sentiment data. Handle gracefully: if sentiment_overall is null, use sector-level sentiment as a proxy.

Pitfall: Weekend/Holiday Data

Running scans on Sunday will return Friday's closing data for equities. Crypto is 24/7. Always check quote.lastUpdate timestamp and note data age in the output.

Timezone Considerations

  • US Markets: 9:30-16:00 ET (14:30-21:00 UTC)
  • Pre-market: 4:00-9:30 ET
  • After-hours: 16:00-20:00 ET
  • EU Markets: 8:00-16:30 CET (various)
  • Asia Markets: Various (check per exchange)
  • Scanner runs at 23:00 ET: All markets closed except crypto

Error Handling Patterns

Robust MCP Call Pattern
// In your CLAUDE.md or skill file:

When calling MCP tools, follow this error handling pattern:

1. If GetMarketOverview fails → retry once after 5 seconds
   If still fails → use cached regime from yesterday's scan
2. If RunScreener returns 0 results → loosen conditions by 10%
   Example: rsi14 < 30 → rsi14 < 35
3. If QueryData returns partial data (some symbols missing) →
   continue with available data, note missing symbols in output
4. If GetInstruments fails for a candidate →
   use QueryData fallback (less data but still usable)
5. Never generate setups without fresh quote validation
