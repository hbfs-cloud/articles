The Problem With Manual Trading Research

If you are a retail trader doing your own research, your workflow probably looks something like this: you open TradingView, flip through a watchlist of 30-50 tickers, check RSI and MACD on each, maybe read some news, glance at earnings dates, and then try to synthesize all of that into a trade decision. On a good day, this takes 2-3 hours. On a busy day, you skip it entirely.

The problems with this approach are structural, not personal:

  • Coverage is pathetically narrow. You cannot manually screen 8,000 tickers. So you miss opportunities in names you have never heard of. The best setups often come from obscure mid-caps that never make it to FinTwit.
  • Analysis is inconsistent. Monday-you applies different criteria than Friday-you. Your emotional state, your recent P&L, whether you slept well — all of these introduce noise into your selection process.
  • Multi-dimensional scoring is impossible at scale. Checking technicals is easy. But simultaneously evaluating technicals + fundamentals + social sentiment + sector rotation + macro regime + AI conviction for hundreds of candidates? That requires compute, not willpower.
  • There is no feedback loop. Did your screening criteria actually produce profitable setups? Without systematic tracking, you are flying blind. You cannot improve what you do not measure.
  • Opportunity cost is enormous. Those 2-3 hours could be spent on actual edge — studying market microstructure, backtesting strategies, or simply living your life.

What "Automated" Actually Means

Let us be precise about terminology, because "automated trading" means different things to different people:

  • Automated execution (algo trading) = a bot places orders on your behalf. We are NOT building this. Automated execution requires brokerage API integration, real-time risk management, latency optimization, and regulatory compliance. That is a different (and much more dangerous) project.
  • Automated research (what we are building) = an AI agent performs all the research, analysis, and scoring that a human analyst would do, and delivers structured trade recommendations. You make the final execution decision.

This distinction matters enormously. Our system is a research automation pipeline, not a trading bot. It replaces the analyst, not the trader. You retain full control over execution, sizing, and risk management. The AI handles the tedious, high-volume, multi-dimensional screening work that no human can do consistently at scale.

Data Flow in Detail

Let us trace a single execution from trigger to delivery. Understanding this flow is essential before we start building, because every architectural decision serves a specific purpose in this chain.

Trigger

A Discord bot (or cron job) executes claude -p "scan du jour" inside a tmux session. The -p flag runs Claude Code in non-interactive (pipe) mode, meaning it reads the prompt, executes, and exits. The working directory is the articles repository, so Claude Code automatically loads CLAUDE.md as its system prompt.

Regime Detection

Claude Code's first MCP call is RunAutoScreener. This is not a simple stock screener — it first analyzes the current market regime by examining VIX levels, yield curves, sector rotation patterns, and breadth indicators. The regime (Risk-On, Risk-Off, Neutral, Transition, Early Risk-On, Early Risk-Off) determines which screening strategies to prioritize. In a Risk-Off regime, for example, the system increases allocation to short setups and hedges (GLD, TLT, SH, SQQQ).

Multi-Strategy Screening

Three RunScreener calls execute in sequence, each with a different DSL (Domain-Specific Language) strategy: oversold reversals, momentum continuation, and breakout setups. Additional screeners target EU equities (VGK, EWG, EWQ, SAP, ASML), APAC names (EWJ, EWY, FXI), and thematic ETFs (XLF, XLE, GLD, ARKK). The combined candidate pool typically contains 100-200 names.

Data Enrichment

For every candidate that passes initial screening, Claude Code calls QueryData with types including quote, insider_transactions, sentiment_overall, trading_signals, support_resistance, and volume_profile. This enrichment step is where most of the API calls happen — easily 50+ calls per scan. The MCP Gateway handles batching and rate limiting internally.

6-Layer Scoring

Each enriched candidate is scored across six dimensions (detailed in Section 4). Claude Code computes a composite score using weights that adapt to the current regime. Only candidates scoring above 85/100 survive this filter. Typically, 20-30 out of 150+ candidates make the cut.

AI Re-Ranking

The survivors are passed to LLMAnalysis (DeepSeek) for a second-opinion AI analysis. This catches edge cases that the scoring system might miss — for example, a ticker with great technicals but a pending SEC investigation, or a setup that looks like a value trap. The AI re-ranking reduces the list to the final 10 A+ setups.

Delivery

Three outputs are generated simultaneously: (1) a full HTML report committed to GitHub Pages via git add/commit/push, (2) Discord alerts for the top 3 A++ setups via the Discord MCP server, and (3) price-level alerts via the Market Alerts MCP server that will fire when entry zones are hit.

Why MCP is the Key Enabler

The Model Context Protocol is what makes this entire architecture possible. Before MCP, connecting an LLM to external data sources required custom API wrappers, prompt engineering for tool calling, and fragile output parsing. MCP standardizes the interface: every data source, every action, every delivery mechanism exposes the same JSON-RPC protocol. Claude Code does not know (or care) whether it is talking to a market data API, a Discord webhook, or a Git repository. It just makes tool calls.

This has three profound implications for our architecture:

  1. Composability. Adding a new data source (say, on-chain crypto data) means adding a new MCP server. Zero changes to the pipeline code, zero changes to the prompt. Claude Code discovers the new tools automatically.
  2. Reliability. MCP servers handle their own retry logic, rate limiting, and error handling. The AI agent sees clean tool responses, not raw HTTP errors.
  3. Testability. Each MCP server can be tested in isolation. You can mock the DailyTickers Gateway to run the pipeline on historical data for backtesting.

MCP in 30 Seconds

The Model Context Protocol (MCP) is an open standard created by Anthropic for connecting AI models to external tools and data. Think of it like USB for AI: a universal connector that lets any AI model talk to any data source. An MCP server exposes "tools" (functions the AI can call) and "resources" (data the AI can read). Claude Code is an MCP client that can connect to multiple servers simultaneously, composing their capabilities into a single workflow.

Architecture Constraints

Before we move on, it is important to document the deliberate constraints in this architecture, because they prevent common mistakes:

  • No automated execution. The pipeline produces recommendations, not orders. There is no brokerage API integration. This is a research tool, not an algo trading system.
  • Single-threaded execution. Claude Code runs as a single agent per pipeline invocation. We do not parallelize multiple scans — this ensures consistent reasoning and prevents race conditions in data collection.
  • Append-only reporting. Every scan produces a new HTML report in a dated directory (scanner/YYYYMMDD/). We never overwrite historical reports. This creates an immutable audit trail.
  • Human-in-the-loop on retrospectives. While daily scans are fully automated, weekly retrospectives (where we grade the scanner's performance) are triggered by the same bot but reviewed by a human before publishing adjustments to scoring weights.
  • Conservative regime adaptation. In Risk-Off or Transition regimes, the system does not just change stock selection — it mandates minimum 20% allocation to hedges and shorts. This is hardcoded in the system prompt, not left to the AI's discretion.

The Tech Stack

Let us break down every component in the stack, what it does, and why we chose it. This is an opinionated stack — there are alternatives for every layer — but these components work together exceptionally well.

Claude Code CLI

The central orchestrator. Claude Code is Anthropic's official CLI for the Claude model family. Unlike the web interface or API, Claude Code can execute shell commands, read and write files, and — critically — connect to MCP servers. When invoked with claude -p "prompt", it runs in non-interactive pipe mode: it reads the prompt, processes it using the system instructions from CLAUDE.md, makes whatever tool calls are necessary, and exits. This makes it perfect for scheduled automation.

Claude Code also maintains a CLAUDE.md file in the project root that acts as persistent memory. Our CLAUDE.md is over 400 lines of instructions that define the scanning methodology, scoring criteria, output format, and delivery mechanism. The AI follows these instructions deterministically on every run.

Model Context Protocol (MCP)

The communication layer. MCP is a JSON-RPC-based protocol that standardizes how AI models interact with external tools. Each MCP server exposes a set of "tools" (callable functions) that the AI can invoke. The protocol handles serialization, transport (stdio or HTTP/SSE), and error propagation. Our pipeline uses three MCP servers simultaneously, and Claude Code manages the connections automatically.

Key MCP concepts: Tools are functions the AI calls (e.g., GetMarketOverview). Resources are data the AI reads (e.g., a JSON dataset). Prompts are templates that structure AI interactions. We primarily use tools.

DailyTickers MCP Gateway

The data layer. This is our custom MCP server that provides access to 58 types of market data via a unified interface. Under the hood, it aggregates data from multiple providers (Yahoo Finance, Alpha Vantage, Polygon, Finnhub, social sentiment APIs) into a consistent schema. The key tools are:

  • GetMarketOverview — Full market snapshot: indices, commodities, crypto, rates, VIX, sentiment, regime classification, and top news stories.
  • QueryData — Flexible data query supporting 58 types: quotes, OHLCV bars, technicals, financials, earnings, insider transactions, options chains, analyst actions, support/resistance levels, volume profiles, sentiment scores, and more.
  • RunAutoScreener — Intelligent screener that first detects the market regime, then runs regime-appropriate screening strategies.
  • RunScreener — Custom screener using a DSL (Domain-Specific Language) for defining screening criteria.
  • GetInstruments — Deep analysis of specific symbols, returning comprehensive data across all 58 types.
  • LLMAnalysis — Secondary AI analysis via DeepSeek for cross-validation.

Discord MCP Server

The notification layer. A lightweight MCP server that exposes Discord API operations as tools. Claude Code can send messages, embeds, and attachments to specified channels. For our pipeline, the Discord server is configured to post to a #scanner-alerts channel with rich embeds that include the ticker, setup type, entry/stop/TP levels, the score breakdown, and a link to the full report on GitHub Pages.

The Discord server also serves as the trigger mechanism: a Discord bot listens for scheduled commands (e.g., every weekday at 23:00 articles scan du jour) and invokes Claude Code via claude -p in a tmux session.

Market Alerts MCP Server

The monitoring layer. This server manages persistent price alerts that fire when specific conditions are met. When the scanner identifies an A++ setup with an entry zone at $45.20-$45.80, it creates an alert that monitors the price in real-time. When the price enters the zone, a Discord notification fires immediately, giving you a heads-up that the setup is actionable. Alerts support multiple condition types: price above/below, percentage change, volume spike, and custom expressions.

Scheduling (Discord Bot + tmux)

The trigger layer. Rather than using system cron (which has limited error handling and no easy way to inspect logs), we use a custom Discord bot that manages schedules via a JSON configuration file. The bot runs Claude Code inside tmux sessions, which means: (1) sessions persist even if the bot restarts, (2) you can attach to a running session to inspect progress in real-time, and (3) output is captured for debugging. The bot supports day-of-week filters, time zones, and manual trigger commands (run #1 to execute a schedule immediately).

GitHub Pages (Reporting)

The archive layer. Every scanner report, every analysis, every weekly briefing is a static HTML file committed to a Git repository and served via GitHub Pages. This gives us: (1) an immutable audit trail of every recommendation, (2) free hosting with global CDN, (3) version history via Git, and (4) easy integration with the pipeline (Claude Code can git add, git commit, and git push as part of its normal tool calls). The report site serves as both the public-facing archive and the internal dashboard for tracking scanner performance.

A++ Selection Criteria

This is the heart of the system. Everything else — the MCP plumbing, the scheduling, the Discord delivery — is infrastructure. The scoring system is the actual edge. It determines what gets recommended and what gets filtered out. Getting this right is the difference between a system that produces noise and one that produces alpha.

Our scoring model evaluates every candidate across 6 independent dimensions. Each dimension produces a score from 0 to 100. The composite score is a weighted average, with weights that shift based on the current market regime. A candidate must score above 85 on the composite AND above the individual threshold on EVERY dimension to qualify as A+. The top 3 candidates by composite score are labeled A++.

Why 6 Dimensions?

Single-dimension screening is how you blow up your account. A stock with a perfect RSI oversold signal means nothing if the company is going bankrupt (fundamentals), the sector is rotating out (sector), the overall market is crashing (macro), social media is screaming about fraud (social), and the AI detects an earnings trap (conviction). Every dimension is a veto gate. All 6 must pass. This is what makes A++ setups so rare — and so reliable.

1
Technical Confluence
Threshold: >= 4 signals aligned

We require at least 4 independent technical signals to confirm the setup. This is not "RSI is oversold, buy." This is multi-timeframe confluence:

  • Price at key support/resistance (S/R from volume profile)
  • RSI divergence (bullish or bearish) on daily AND weekly
  • MACD crossover or histogram reversal
  • Volume confirmation (above 20-day average on signal bar)
  • EMA alignment (8 > 21 > 50 for bullish, inverse for bearish)
  • Bollinger Band squeeze breakout
  • Fibonacci retracement to 0.618 or 0.786 level
  • Candlestick pattern (hammer, engulfing, morning star)

The system checks all 8 signals and requires at least 4 to be present and aligned in the same direction. Conflicting signals (e.g., bullish RSI divergence but bearish EMA alignment) reduce the technical score.

2
Fundamental Quality
Threshold: score >= 80/100

Fundamental analysis prevents us from buying cheap garbage. The fundamental score aggregates:

  • Earnings quality: EPS trend (last 4 quarters), earnings surprise history, revenue growth rate
  • Balance sheet: Debt/equity ratio, current ratio, free cash flow yield
  • Valuation: Forward P/E vs. sector median, PEG ratio, EV/EBITDA
  • Insider activity: Net insider buying in last 90 days (strong signal when executives buy with their own money)
  • Analyst consensus: Mean target vs. current price, number of recent upgrades/downgrades

For ETFs and crypto, the fundamental score adapts: ETFs are scored on tracking error, expense ratio, and AUM. Crypto is scored on network activity, TVL, and developer activity.

3
Social Sentiment
Threshold: aligned with trade direction

Social sentiment is not a contrarian indicator — it is a confirmation signal. We want sentiment aligned with our trade direction, but not euphoric (which would indicate we are late):

  • StockTwits: Message volume trend, bullish/bearish ratio, change from 7-day average
  • Reddit (WSB, stocks): Mention frequency, sentiment polarity, DD post quality
  • News sentiment: NLP score across last 50 articles, headline vs. body sentiment divergence
  • Short interest: Days to cover, short % of float, cost to borrow changes

The ideal social profile for a long setup: moderately bullish sentiment with rising mention volume but below the "hype" threshold. If everyone on WSB is screaming about a ticker, we are too late.

4
Sector Trend
Threshold: sector outperforming SPY on 5d/20d

Swimming against the sector tide is a losing strategy. We want our picks in sectors that are gaining relative strength:

  • Relative strength: Sector ETF performance vs. SPY over 5-day and 20-day windows
  • Fund flows: Net inflows/outflows to sector ETFs (XLK, XLF, XLE, etc.)
  • Rotation signal: Which sectors are gaining/losing institutional allocation (derived from 13F filings and ETF flows)
  • Earnings season: If the sector is mid-earnings season, have the early reporters beaten or missed?

A setup in a sector that is underperforming SPY by more than 2% over 20 days gets an automatic downgrade, regardless of how good the individual stock looks.

5
Macro Regime
Threshold: compatible with detected regime

The macro layer ensures we are not fighting the market. The regime detection algorithm classifies the current environment into one of six states:

  • Risk-On: VIX < 18, yield curve positive, breadth > 60%. Favor growth, momentum, high-beta.
  • Early Risk-On: VIX declining from spike, breadth recovering. Favor oversold quality names.
  • Neutral: Mixed signals. Favor sector leaders and range-bound strategies.
  • Transition: Regime change in progress. Reduce position sizes, favor hedges.
  • Early Risk-Off: VIX rising, breadth deteriorating. Start building short/hedge positions.
  • Risk-Off: VIX > 25, yield curve flat/inverted, breadth < 40%. Favor shorts, puts, GLD, TLT.

A long-only momentum setup in a Risk-Off regime fails the macro check automatically. The system will not even score it further — it is immediately rejected.

6
AI Conviction
Threshold: conviction >= 85%

The final layer is the AI's own judgment, applied after all quantitative scores are computed. Claude Code synthesizes all available information and assigns a conviction percentage:

  • Pattern recognition: Has the AI seen this setup pattern before? What was the historical outcome?
  • Risk/reward asymmetry: Does the entry-to-stop distance justify the potential reward?
  • Catalyst timing: Is there an upcoming earnings, FDA decision, or macro event that could invalidate the setup?
  • Cross-validation: Does the DeepSeek second-opinion analysis agree with the primary scoring?
  • Anti-trap detection: Is this a value trap, a dead cat bounce, or a short squeeze setup that reverses violently?

The AI conviction layer is deliberately subjective. It captures the holistic reasoning that quantitative scores cannot — the "this just does not look right" instinct that experienced traders develop over decades.

The composite score is a weighted average that adapts to market regime. Here are the weight profiles:

Notice how the weights shift: in Risk-Off, macro weight jumps to 0.30 because fighting the macro trend is suicidal. In Risk-On, sector weight rises to 0.20 because riding the right sector wave amplifies returns. Social sentiment weight drops in Risk-Off because social media becomes unreliable in panics (too much noise).

From A+ to A++

The scoring system produces A+ setups (composite >= 85, all dimensions pass). But we go one step further to identify A++ — the absolute cream. The A++ designation requires:

  1. Composite score >= 90 (not just 85)
  2. No dimension below 75 (no weak links)
  3. R:R >= 2:1 (the reward must be at least 2x the risk)
  4. AI re-ranking confirmation (DeepSeek must independently rate the setup as "high conviction")
  5. No upcoming binary event within 5 trading days (no earnings, FDA, FOMC directly ahead that could invalidate the thesis)

On any given night, the scanner might produce 10 A+ setups but only 2-3 A++ setups. Some nights produce zero A++. That is fine — we would rather miss a mediocre opportunity than recommend one. A++ is about precision, not recall.

The Anti-Recency Bias Filter

One critical filter that is easy to overlook: the system maintains a "recently recommended" list. Any ticker that appeared in the last 3 scanner reports is automatically deprioritized unless it has a materially different setup type (e.g., it was a momentum play last week but is now an oversold reversal). This prevents the scanner from falling in love with the same names and ensures at least 70% fresh tickers per scan.

Retrospective Learning

Before scanning anything, Claude Code reads every file in scanner/retrospective/*/index.html. These are weekly performance reviews that grade the scanner. From each retrospective, the AI extracts:

  • Average P&L by sector

Previous Scan Analysis

Claude Code reads the most recent scanner/YYYYMMDD/index.html to extract the 10 tickers from the last scan. These go into the anti-doublon filter: the new scan must contain at least 70% fresh tickers. This prevents the scanner from recommending the same names night after night.

anti-doublon logic (conceptual)
previous_tickers = extract_tickers(last_scan)  # e.g., [AAPL, NVDA, GLD, ...]
new_candidates = score_and_rank(all_candidates)

# Enforce 70% freshness
fresh_count = 0
for candidate in new_candidates:
    if candidate.ticker in previous_tickers:
        candidate.score *= 0.7  # 30% penalty for repeat
    else:
        fresh_count += 1

# If fresh_count < 7, expand screening to find more unique names

23:12:00

6-Layer Scoring

Claude Code now has all the data needed to score each candidate. It computes the 6 dimension scores, applies the regime-adjusted weights, and calculates the composite score. This is where the AI's reasoning ability matters — it is not just running formulas, it is interpreting the data contextually:

Scoring Logic (Claude Code's internal reasoning)
For each candidate:
  1. Technical Score
     - Count aligned signals from trading_signals + support_resistance
     - Check multi-timeframe confirmation (daily vs weekly)
     - Score: (aligned_signals / 8) * 100, with bonuses for rare confluences

  2. Fundamental Score
     - Extract EPS trend from earnings_quarterly
     - Check insider_transactions for net buying
     - Compare valuation metrics to sector medians from financials
     - Score: weighted aggregate of sub-scores

  3. Social Score
     - Parse sentiment_overall for bullish/bearish ratio
     - Check if sentiment is rising but below "euphoria" threshold
     - Score: alignment * magnitude * freshness

  4. Sector Score
     - Compare sector ETF performance vs SPY (5d, 20d)
     - Check if sector is in the "leading" list from regime analysis
     - Score: relative_strength * 100, capped at 100

  5. Macro Score
     - Is the setup type compatible with current regime?
     - Long momentum in Risk-On? Score = 95
     - Long momentum in Risk-Off? Score = 20 (auto-fail)
     - Score: compatibility * regime_confidence * 100

  6. AI Conviction
     - Synthesize all data points holistically
     - Check for red flags: upcoming earnings, FDA, FOMC
     - Estimate R:R from entry to S/R levels
     - Score: subjective assessment 0-100

  Composite = sum(weight_i * score_i) for i in dimensions
  Pass = composite >= 85 AND all individual scores >= threshold

23:18:00

Price Validation (P0 Control)

Before finalizing the selection, a critical sanity check runs: for every selected ticker, Claude Code calls QueryData with types: quote to get the real-time spot price. If the calculated entry price differs by more than 10% from the current market price, the setup is rejected. This catches stale data issues, stock splits, and ticker symbol errors:

P0 Validation
for each selected_setup:
  spot_price = QueryData(symbols=[setup.ticker], types=["quote"]).price
  entry_price = setup.entry_zone_midpoint

  deviation = abs(spot_price - entry_price) / spot_price
  if deviation > 0.10:
    REJECT setup  # Entry price too far from reality
    log("P0 FAIL: {ticker} spot={spot_price} entry={entry_price} dev={deviation}")

Geographic Diversification Enforcement

The final 10 setups must meet geographic diversification requirements:

  • Minimum 5 US equities
  • Minimum 2 European equities or ETFs
  • Minimum 1 Asia-Pacific name
  • Minimum 2 thematic/sector ETFs

If the scoring naturally produces 10 US names, Claude Code replaces the lowest-scoring US names with the highest-scoring EU, APAC, and ETF candidates — even if their absolute scores are lower. This prevents home bias and ensures global coverage.

Additionally, in Risk-Off or Early Risk-Off regimes, at least 20% of setups (2 out of 10) must be defensive: short positions, inverse ETFs (SH, SQQQ), or safe havens (GLD, TLT).

Step 5: Create the CLAUDE.md System Prompt

The CLAUDE.md file is the brain of the operation. It contains all the instructions that Claude Code follows during automated runs. Here is a minimal skeleton to get started — the full version we use in production is 400+ lines:

CLAUDE.md (starter template)
# CLAUDE.md - Automated Trading Pipeline

## Project Overview
Automated trading research pipeline using Claude Code + MCP.
Publishes scanner reports, daily briefings, and ticker analyses.

## MCP Gateway
Available tools:
- `mcp__dailytickers__GetMarketOverview` — Full market snapshot
- `mcp__dailytickers__QueryData` — 58 data types
- `mcp__dailytickers__RunAutoScreener` — Regime-aware screening
- `mcp__dailytickers__RunScreener` — Custom DSL screening
- `mcp__dailytickers__GetInstruments` — Deep symbol analysis
- `mcp__dailytickers__LLMAnalysis` — DeepSeek second opinion

## Scanner Command ("scan du jour")

### Step 1: Read Retrospectives
Read ALL files in `scanner/retrospective/*/index.html`.
Extract: hit rates, flop tickers, strategy adjustments.

### Step 2: Read Previous Scan
Read the most recent `scanner/YYYYMMDD/index.html`.
Extract the 10 tickers for anti-doublon filter (70% new minimum).

### Step 3: Regime Detection
Call `RunAutoScreener` to detect market regime.
Regimes: Risk-On, Early Risk-On, Neutral, Transition,
         Early Risk-Off, Risk-Off.

### Step 4: Multi-Strategy Screening
Run 3 DSL strategies:
1. Oversold: RSI(14) < 35 AND SMA(50) > SMA(200) AND Volume spike
2. Momentum: Close > SMA(20) > SMA(50) AND RSI 55-75 AND ADX > 25
3. Breakout: Close > BB_Upper AND Volume > 2x average

Additional screens: EU (VGK, SAP, ASML...), APAC (EWJ, FXI...),
ETFs (XLF, GLD, TLT, ARKK...).

### Step 5: Scoring (6 Layers)
For top 30 candidates, score across:
1. Technical confluence (>= 4 signals)
2. Fundamental quality (>= 80/100)
3. Social sentiment (aligned with direction)
4. Sector trend (outperforming SPY)
5. Macro regime (compatible)
6. AI conviction (>= 85%)

Composite >= 85 = A+. Top 3 with >= 90 = A++.

### Step 6: Output
- Create `scanner/YYYYMMDD/index.html` (> 40KB)
- Run `node tools/add_card.js scanner/YYYYMMDD/index.html`
- Git add, commit, push
- Send top 3 A++ to Discord

### Constraints
- Geographic diversity: min 5 US + 2 EU + 1 APAC + 2 ETF
- Risk-Off: min 20% defensive setups
- Anti-doublon: min 70% new tickers vs previous scan
- P0 control: reject if entry price > 10% from spot

The Power of CLAUDE.md

This file IS the trading strategy. When you want to add a new scoring dimension, change the geographic allocation, adjust the A++ threshold, or modify the output format, you edit this file. No code changes, no deployments, no compilation. Claude Code reads it fresh on every invocation. This is why AI-orchestrated systems are fundamentally different from traditional automation: the strategy lives in natural language, not in compiled code.

Troubleshooting Common Setup Issues

Issue Symptom Fix
MCP server not found Error: Tool mcp__dailytickers__* not available Check claude_desktop_config.json path. Run node /path/to/dist/index.js manually to verify the server starts.
API key invalid 401 Unauthorized in server logs Verify MW_API_KEY in the config. Check the key has not expired.
CLAUDE.md not loaded Claude Code does not follow scanning instructions Ensure you are running claude -p from the project root where CLAUDE.md lives. Use pwd to verify.
Git push fails Permission denied (publickey) Set up SSH key: ssh-keygen -t ed25519 and add to GitHub. Or use gh auth login for HTTPS.
Discord bot offline Schedules do not fire Check tmux session: tmux attach -t discord-bot. Look for crash logs. Restart if needed.
Scanner report too small HTML file < 10KB Claude Code may have been truncated. Increase the max_tokens setting or split the generation into multiple write operations.
Rate limiting 429 Too Many Requests Reduce MW_MAX_CONCURRENT to 5. Increase MW_CACHE_TTL to reduce API calls.
