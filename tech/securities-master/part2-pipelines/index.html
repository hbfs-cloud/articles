High-Velocity Ingestion:
Go, Meltano, and Airflow on Nomad

Python cannot scale to fetch 100,000 instruments concurrently. We tackle ingestion with custom Go Extractors, package them into Meltano Docker images, and orchestrate complex ETL DAGs using Apache Airflow on HashiCorp Nomad.

In Part 1, we defined what a point-in-time correct architecture looks like. However, observing tier-1 hedge fund codebases—such as reference-service and execution-instruments repositories—reveals massive complexity. We must model EQUITY, ETF, FUTURE, FUTURES_SPREAD, INDEX, RATE, FXFORWARD, IRS, OPTIONVOL, and CRYPTO.

When ingesting data for this massive universe across multiple disparate providers (Yahoo Finance, StockAnalysis, Casablanca Bourse, Binance, FRED), standard Python ELT loops (like Airbyte or basic Python Singer Taps) fail due to execution speed and Global Interpreter Lock (GIL) networking bottlenecks.

Our hedge-fund grade solution involves:

  1. Raw Zone Database Schema (dump first, transform later).
  2. Custom Go Meltano Extractor (Tap) handling the specific API limits and pagination logic natively.
  3. Docker Packaging of the Go binary along with the Python Meltano environment.
  4. Workflow Orchestration with Apache Airflow triggering HashiCorp Nomad tasks. Because Nomad's internal periodic cron is not enough for complex DAGs (Extract → Load → dbt Transform).

The Raw PostgreSQL Schema

In the Modern Data Stack paradigm (ELT), we extract and load purely raw data first. Complex joins and SCD Type 2 logic are handled by dbt subsequently. Our raw ingestion tables are optimized for ultra-fast COPY commands. 

-- raw_zone.instruments
CREATE TABLE raw_zone.instruments (
    external_id VARCHAR(100),       -- e.g. BVC Drupal ID, Yahoo ticker
    provider_name VARCHAR(50),      -- 'YAHOO', 'BVC', 'STOCKANALYSIS'
    symbol VARCHAR(50), 
    isin VARCHAR(20),
    instrument_type VARCHAR(50),    -- 'EQUITY', 'CRYPTO', 'OPTIONVOL'
    
    raw_payload JSONB,              -- Store the exact API response for audit
    ingested_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- raw_zone.market_data
CREATE TABLE raw_zone.market_data (
    provider_name VARCHAR(50) NOT NULL,
    symbol VARCHAR(50) NOT NULL,
    trade_date TIMESTAMP WITH TIME ZONE NOT NULL,
    
    open_price NUMERIC(20, 8),
    high_price NUMERIC(20, 8),
    low_price NUMERIC(20, 8),
    close_price NUMERIC(20, 8),
    adj_close NUMERIC(20, 8),
    volume NUMERIC(20, 8),
    
    ingested_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    PRIMARY KEY (provider_name, symbol, trade_date)
) PARTITION BY LIST (EXTRACT(YEAR FROM trade_date));
-- Note: Sub-partitioning per provider is recommended for massive datasets.

Custom Meltano Tap in Go

Go’s concurrency model is unmatched for IO-bound work like fetching thousands of tickers simultaneously. To integrate smoothly with Meltano, we make our Go binary speak the Singer Protocol. It communicates purely through standard output (stdout) using JSON messages: SCHEMA (to define the PostgreSQL table), and RECORD (the actual data payload).

Below is a concrete implementation snippet showing how we handle Yahoo Finance JSON parsing and Casablanca (BVC) API pagination within a concurrent semantic.

// tap-marketdata/main.go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"os"
	"sync"
	"time"
)

// Singer JSON Schema Message
type SingerMessage struct {
	Type   string      `json:"type"`
	Record interface{} `json:"record,omitempty"`
	Stream string      `json:"stream,omitempty"`
}

// Our unified Target Data format
type OHLCVRecord struct {
	ProviderName string  `json:"provider_name"`
	Symbol       string  `json:"symbol"`
	TradeDate    string  `json:"trade_date"`
	OpenPrice    float64 `json:"open_price"`
	HighPrice    float64 `json:"high_price"`
	LowPrice     float64 `json:"low_price"`
	ClosePrice   float64 `json:"close_price"`
	AdjClose     float64 `json:"adj_close,omitempty"`
	Volume       float64 `json:"volume"`
}

func emitRecord(stream string, record interface{}) {
	msg := SingerMessage{ Type: "RECORD", Stream: stream, Record: record }
	b, _ := json.Marshal(msg)
	fmt.Println(string(b))
}

// Example: Concurrency-bounded Yahoo Fetcher
// ---------------------------------------------------------
func syncYahoo(symbols []string) {
	const maxConcurrency = 50
	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup

	for _, sym := range symbols {
		wg.Add(1)
		go func(ticker string) {
			defer wg.Done()
			sem <- struct{}{}
			defer func() { <-sem }()

			// Genuine HTTP request mimicking institutional Go clients
			url := fmt.Sprintf("https://query2.finance.yahoo.com/v8/finance/chart/%s?range=5d&interval=1d", ticker)
			req, _ := http.NewRequest("GET", url, nil)
			req.Header.Set("User-Agent", "Mozilla/5.0")

			client := &http.Client{Timeout: 10 * time.Second}
			resp, err := client.Do(req)
			if err != nil || resp.StatusCode != 200 { return }
			defer resp.Body.Close()

			// Parse Yahoo's specific format
			var result struct {
				Chart struct {
					Result []struct {
						Timestamp []int64 `json:"timestamp"`
						Indicators struct {
							Quote []struct {
								Open   []float64 `json:"open"`
								High   []float64 `json:"high"`
								Low    []float64 `json:"low"`
								Close  []float64 `json:"close"`
								Volume []float64 `json:"volume"`
							} `json:"quote"`
						} `json:"indicators"`
					} `json:"result"`
				} `json:"chart"`
			}
			json.NewDecoder(resp.Body).Decode(&result)

			if len(result.Chart.Result) > 0 {
				r := result.Chart.Result[0]
				q := r.Indicators.Quote[0]
				for i, ts := range r.Timestamp {
					emitRecord("raw_market_data", OHLCVRecord{
						ProviderName: "YAHOO",
						Symbol:       ticker,
						TradeDate:    time.Unix(ts, 0).Format(time.RFC3339),
						OpenPrice:    q.Open[i],
						HighPrice:    q.High[i],
						LowPrice:     q.Low[i],
						ClosePrice:   q.Close[i],
						Volume:       q.Volume[i],
					})
				}
			}
		}(sym)
	}
	wg.Wait()
}

// ---------------------------------------------------------
// Example: Rate-limited BVC (Casablanca) Pagination Fetcher
// ---------------------------------------------------------
func syncCasablancaBVC() {
	url := "https://api.casablanca-bourse.com/fr/api/bourse_data/instrument?page[limit]=200"
	client := &http.Client{Timeout: 30 * time.Second}

	for url != "" {
		req, _ := http.NewRequest("GET", url, nil)
		resp, err := client.Do(req)
		if err != nil { break }

		body, _ := io.ReadAll(resp.Body)
		resp.Body.Close()

		var result struct {
			Data []struct {
				Attributes struct {
					Symbol   string `json:"symbol"`
					CodeISIN string `json:"codeISIN"`
				} `json:"attributes"`
			} `json:"data"`
			Links struct {
				Next struct { Href string `json:"href"` } `json:"next"`
			} `json:"links"`
		}
		json.Unmarshal(body, &result)

		for _, rec := range result.Data {
			// Emit JSON payload for further normalization in dbt
			emitRecord("raw_instruments", map[string]interface{}{
				"provider_name":   "BVC",
				"symbol":          rec.Attributes.Symbol,
				"isin":            rec.Attributes.CodeISIN,
				"instrument_type": "EQUITY", // Default for BVC listings
				"raw_payload":     rec.Attributes,
			})
		}

		if result.Links.Next.Href != "" {
			url = result.Links.Next.Href
			time.Sleep(200 * time.Millisecond) // Strict rate limit for BVC API
		} else {
			url = ""
		}
	}
}

func main() {
    // 1. Output Singer Schema (omitted for brevity)
    // 2. Fetch all data
	syncYahoo([]string{"AAPL", "MSFT", "IWM", "BTC-USD"}) // High concurrency
	syncCasablancaBVC()                                   // Sequential & Rate-limited
}

Packaging Meltano & Go into a single Image

A crucial integration step: Meltano expects to invoke an executable file. We must compile our Go code and inject it into a Python-based Meltano Docker container.

# 1. Build the Go Singer Extractor
FROM golang:1.22 AS builder
WORKDIR /app
COPY go.mod ./
COPY main.go ./
# Compile statically to ensure it runs anywhere
RUN CGO_ENABLED=0 GOOS=linux go build -o tap-marketdata-go main.go

# 2. Build the Meltano Runtime
FROM meltano/meltano:v3.1.0-python3.9
WORKDIR /project

# Install the target database loader
RUN meltano add loader target-postgres --variant transferwise

# Copy our compiled Go binary
COPY --from=builder /app/tap-marketdata-go /usr/local/bin/tap-marketdata-go
RUN chmod +x /usr/local/bin/tap-marketdata-go

# Copy Meltano configurations
COPY meltano.yml .

ENTRYPOINT ["meltano"]

Orchestration: Airflow on HashiCorp Nomad

A simple Nomad periodic cron job is completely insufficient for a robust data platform. We need a proper scheduler (Apache Airflow or Dagster) to map out dependencies: Extract/Load (Meltano) → Transform (dbt) → Corporate Action Merges.

We host Apache Airflow, and configure its Directed Acyclic Graphs (DAGs) to trigger executions remotely on HashiCorp Nomad using the NomadOperator (or Nomad HTTP API). This maintains Nomad as the sole compute allocator while giving Airflow control over the workflow logic. 

# airflow_dags/securities_master_dag.py
from datetime import datetime
from airflow import DAG
from airflow.providers.hashicorp.operators.nomad import NomadOperator

default_args = {
    'owner': 'data-engineering',
    'start_date': datetime(2026, 1, 1),
    'retries': 2,
}

with DAG('securities_master_daily_ingest', default_args=default_args, schedule_interval='0 23 * * 1-5') as dag:

    # 1. Trigger Meltano Container on Nomad Cluster
    # Injects PostgreSQL Vault secrets securely at runtime.
    meltano_extract_load = NomadOperator(
        task_id='meltano_extract_high_concurrency',
        nomad_url='http://nomad.internal.org:4646',
        job_spec="""
            job "marketdata-ingest-run" {
                datacenters = ["dc1"]
                type = "batch"
                group "elt" {
                    task "meltano" {
                        driver = "docker"
                        config {
                            image = "registry.internal.org/data/marketdata-meltano:latest"
                            command = "meltano"
                            args = ["run", "tap-marketdata-go", "target-postgres"]
