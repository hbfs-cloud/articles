High-Velocity Ingestion:
Meltano Taps in Go & Nomad

Forget slow Python scripts. We challenge conventional wisdom by writing high-concurrency Singer Taps in Go to fetch equities, crypto, and static data, then orchestrate the entire Meltano ingestion pipeline natively in Nomad.

In Part 1, we defined what a point-in-time correct architecture looks like. But looking closely at institutional codebases—like the execution-instruments and reference-service components used heavily in large-scale hedge funds—it is clear we must challenge our own scope.

A true hedge-fund instrument suite does not solely support stocks. It models EQUITY, ETF, FUTURE, FUTURES_SPREAD, INDEX, RATE, FXFORWARD, IRS, OPTIONVOL, and CRYPTO. It deals with diverse SettlementTypes and MarketDataSourceTypes. To feed a true Securities Master with such a massive universe spanning multiple asset classes, simple Python crons will fail either on speed, memory limits, or network timeouts.

Our solution: Write a Custom Go Extractor obeying the Singer Specification. We wrap this Go binary in Meltano, output straight into a Raw PostgreSQL Database, and orchestrate the whole dance using HashiCorp Nomad.

Building the Meltano Tap in Go

Go’s concurrency model is unmatched for IO-bound work like fetching thousands of tickers simultaneously from Yahoo, Casablanca (BVC), Binance, and StockAnalysis.

A Singer Tap communicates with Meltano purely through stdout using JSON messages: SCHEMA (to define the table structure), STATE (for incremental loading bookmarks), and RECORD (the actual data).

// main.go - Meltano Tap in Go (tap-marketdata)
package main

import (
	"encoding/json"
	"fmt"
	"os"
	"sync"
	"time"
)

// Singer JSON Schema message Definitions
type SingerMessage struct {
	Type   string      `json:"type"`
	Record interface{} `json:"record,omitempty"`
	Schema interface{} `json:"schema,omitempty"`
	Stream string      `json:"stream,omitempty"`
}

type OHLCVRecord struct {
	Symbol   string  `json:"symbol"`
	Date     string  `json:"date"`
	Open     float64 `json:"open"`
	High     float64 `json:"high"`
	Low      float64 `json:"low"`
	Close    float64 `json:"close"`
	AdjClose float64 `json:"adj_close"`
	Volume   float64 `json:"volume"`
	Source   string  `json:"source"`
}

func emitRecord(stream string, record interface{}) {
	msg := SingerMessage{
		Type:   "RECORD",
		Stream: stream,
		Record: record,
	}
	b, _ := json.Marshal(msg)
	fmt.Println(string(b))
}

func main() {
	// First: Emit SCHEMA for target-postgres to build the table
	emitSchema()

	// Hardcoded for example: In reality, read from config.json passed by Meltano
	symbols := []string{"AAPL", "MSFT", "IWM", "BTC-USD"}

	// Fast Go routines with Semaphore for High-Concurrency Yahoo/Binance fetching
	const maxConcurrency = 50
	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup

	for _, sym := range symbols {
		wg.Add(1)
		go func(symbol string) {
			defer wg.Done()
			sem <- struct{}{}
			defer func() { <-sem }()

			// Pseudo-code wrapper around your actual FetchHistoryYahooJSON
			bars := FetchProviderData(symbol) 

			for _, bar := range bars {
				// Emit row-by-row formatted for target-postgres
				emitRecord("raw_market_data", OHLCVRecord{
					Symbol:   symbol,
					Date:     bar.Date.Format(time.RFC3339),
					Open:     bar.Open,
					High:     bar.High,
					Low:      bar.Low,
					Close:    bar.Close,
					AdjClose: bar.AdjClose,
					Volume:   bar.Volume,
					Source:   bar.Source, // 'YAHOO', 'BVC', 'BINANCE', etc.
				})
			}
		}(sym)
	}

	wg.Wait()
	os.Exit(0)
}

Tying it together in Meltano

We compile our Go program and tell Meltano to treat it as a custom extractor. Meltano will handle the piping of our standard output directly into target-postgres. No intermediate CSV hacking. Raw streaming speed.

# meltano.yml
version: 1
default_environment: dev
environments:
  - name: dev
  - name: prod

plugins:
  extractors:
    - name: tap-marketdata-go
      namespace: tap_marketdata
      executable: ./tap-marketdata-bin  # The statically compiled Go binary
      capabilities:
        - state
        - catalog
      settings:
        - name: start_date
        - name: provider_list
  
  loaders:
    - name: target-postgres
      variant: transferwise
      pip_url: pipelinewise-target-postgres
      config:
        host: ${PG_HOST}
        port: 5432
        user: ${PG_USER}
        password: ${PG_PASSWORD}
        dbname: securities_master
        default_target_schema: raw_zone

The Nomad Scheduling Job

The beauty of the Modern Data Stack is decoupling. We don't need a heavy Airflow setup for this. HashiCorp Nomad is incredibly elegant for running batch or periodic Meltano ELT jobs at the end of the trading day.

Here is the exact Nomad Job specification we deploy to run our ingestion nightly. It pulls our custom Docker image, injects the secrets required for PostgreSQL, and kicks off meltano run.

# marketdata-ingest.nomad.hcl
job "marketdata-ingest" {
  datacenters = ["dc1"]
  type        = "batch"

  periodic {
    cron             = "0 23 * * 1-5"  # Run at 11:00 PM Monday to Friday
    prohibit_overlap = true
    time_zone        = "Europe/Paris"
