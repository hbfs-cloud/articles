Notre Securities Master contient 60+ millions de barres OHLCV ajustées, des snapshots SCD2 de 15 000 instruments, et des marts Gold pré-calculés. Un LLM (Claude, GPT-4, Gemini) ne peut pas ingérer cette volumétrie dans son contexte. La solution : exposer le Securities Master comme un ensemble d'outils structurés que le LLM peut appeler on-demand via le Model Context Protocol (MCP).

Qu'est-ce que le Model Context Protocol (MCP) ?

MCP est un protocole ouvert développé par Anthropic (2024) qui standardise la façon dont les LLMs interagissent avec des systèmes externes. Au lieu que le LLM génère du SQL arbitraire (risque d'injection, accès non contrôlé), il appelle des outils MCP prédéfinis avec un schéma strict.

Architecture : le LLM ↔ MCP Client (dans Claude Desktop/Claude API) ↔ MCP Server (notre Go app) ↔ PostgreSQL (notre Securities Master). Le serveur MCP contrôle exactement quelles données sont exposées et avec quels filtres de sécurité.

Exemple d'interaction LLM ↔ MCP Securities Master
🤖 LLM : "Trouve les 10 meilleures actions momentum du secteur technologie avec un ADV > 50M$"
→ Tool call: get_momentum_candidates({sector: "Technology", min_adv_usd: 50000000, limit: 10})
← Tool result: [{symbol:"NVDA", close:875.4, perf_1m:+18.2%, sma_regime:"Bullish — Golden Cross", adv:2.1B}, ...]
🤖 LLM : "Sur la base de ces données, voici une allocation suggérée avec un sizing de Kelly fractionnaire..."

Implémentation du Serveur MCP

Le serveur MCP est un binaire Go qui écoute sur stdin/stdout (protocole JSON-RPC 2.0 via stdio transport). Claude Desktop ou un client MCP personnalisé lance ce processus et communique via des messages JSON structurés.

go — internal/mcp/types.go (types MCP JSON-RPC) 
package mcp

// Conformité avec la spec MCP v1.0 (Anthropic)

// Tool décrit un outil MCP exposé au LLM
type Tool struct {
    Name        string      `json:"name"`
    Description string      `json:"description"`
    InputSchema InputSchema `json:"inputSchema"`
}

// InputSchema est un JSON Schema décrivant les paramètres de l'outil
type InputSchema struct {
    Type       string              `json:"type"`        // "object"
    Properties map[string]Property `json:"properties"`
    Required   []string            `json:"required,omitempty"`
}

type Property struct {
    Type        string   `json:"type"`
    Description string   `json:"description"`
    Enum        []string `json:"enum,omitempty"`
    Minimum     *float64 `json:"minimum,omitempty"`
    Maximum     *float64 `json:"maximum,omitempty"`
}

// ToolCall est reçu du LLM quand il appelle un outil
type ToolCall struct {
    Name      string                 `json:"name"`
    Arguments map[string]interface{} `json:"arguments"`
}

// ToolResult est renvoyé au LLM après exécution
type ToolResult struct {
    Content []ContentBlock `json:"content"`
    IsError bool           `json:"isError,omitempty"`
}

type ContentBlock struct {
    Type string `json:"type"` // "text"
    Text string `json:"text"`
}
go — internal/mcp/server.go (boucle JSON-RPC stdio) 
package mcp

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
)

// JSONRPCRequest : message entrant du client MCP
type JSONRPCRequest struct {
    JSONRPC string          `json:"jsonrpc"`
    ID      interface{}     `json:"id"`
    Method  string          `json:"method"`
    Params  json.RawMessage `json:"params"`
}

// JSONRPCResponse : message sortant vers le client MCP
type JSONRPCResponse struct {
    JSONRPC string      `json:"jsonrpc"`
    ID      interface{} `json:"id"`
    Result  interface{} `json:"result,omitempty"`
    Error   *RPCError   `json:"error,omitempty"`
}

type RPCError struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
}

// Server gère la boucle de communication MCP via stdio
type Server struct {
    registry *Registry
    scanner  *bufio.Scanner
    encoder  *json.Encoder
}

func NewServer(reg *Registry) *Server {
    return &Server{
        registry: reg,
        scanner:  bufio.NewScanner(os.Stdin),
        encoder:  json.NewEncoder(os.Stdout),
    }
}

func (s *Server) Run() error {
    for s.scanner.Scan() {
        line := s.scanner.Bytes()

        var req JSONRPCRequest
        if err := json.Unmarshal(line, &req); err != nil {
            s.writeError(nil, -32700, "Parse error")
            continue
        }

        switch req.Method {
        // Handshake : le client MCP découvre les capacités du serveur
        case "initialize":
            s.writeResult(req.ID, map[string]interface{}{
                "protocolVersion": "2024-11-05",
                "serverInfo": map[string]string{
                    "name":    "securities-master-mcp",
                    "version": "1.0.0",
                },
                "capabilities": map[string]interface{}{
                    "tools": map[string]bool{"listChanged": false},
                },
            })

        // Liste des outils disponibles
        case "tools/list":
            s.writeResult(req.ID, map[string]interface{}{
                "tools": s.registry.ListTools(),
            })

        // Exécution d'un outil spécifique
        case "tools/call":
            var p struct {
                Name      string                 `json:"name"`
                Arguments map[string]interface{} `json:"arguments"`
            }
            if err := json.Unmarshal(req.Params, &p); err != nil {
                s.writeError(req.ID, -32602, "Invalid params")
                continue
            }

            result, err := s.registry.Execute(p.Name, p.Arguments)
            if err != nil {
                s.writeResult(req.ID, ToolResult{
                    IsError: true,
                    Content: []ContentBlock{{Type: "text", Text: err.Error()}},
                })
                continue
            }
            s.writeResult(req.ID, result)

        default:
            s.writeError(req.ID, -32601, fmt.Sprintf("Method not found: %s", req.Method))
        }
    }
    return s.scanner.Err()
}

func (s *Server) writeResult(id interface{}, result interface{}) {
    _ = s.encoder.Encode(JSONRPCResponse{JSONRPC: "2.0", ID: id, Result: result})
}

func (s *Server) writeError(id interface{}, code int, msg string) {
    _ = s.encoder.Encode(JSONRPCResponse{JSONRPC: "2.0", ID: id, Error: &RPCError{Code: code, Message: msg}})
}

// Definition retourne le schéma MCP de l'outil (exposé au LLM)
func (t *ScreenerTool) Definition() mcp.Tool {
    min0  := float64(0)
    max100 := float64(100)
    return mcp.Tool{
        Name:        "screen_momentum_candidates",
        Description: "Trouve les actions avec le meilleur momentum prix selon les critères donnés. " +

                     "Retourne maximum 'limit' résultats triés par score momentum décroissant.",
        InputSchema: mcp.InputSchema{
            Type: "object",
            Properties: map[string]mcp.Property{
                "sector": {
                    Type:        "string",
                    Description: "Filtrer par secteur GICS (ex: 'Technology', 'Healthcare', 'Energy'). Vide = tous secteurs.",
                },
                "trend_regime": {
                    Type:        "string",
                    Description: "Filtrer par régime de tendance.",
                    Enum:        []string{"Bullish — Golden Cross", "Bullish — Above SMA50", "Bearish — Death Cross", "Bearish — Below SMA50"},
                },
                "min_adv_usd": {
                    Type:        "number",
                    Description: "ADV minimum en USD (Average Daily Volume). Ex: 50000000 pour 50M$.",
                    Minimum:     &min0,
                },
                "min_perf_1m_pct": {
                    Type:        "number",
                    Description: "Performance minimale sur 1 mois en %. Ex: 5 pour +5%.",
                },
                "max_vol_20d": {
                    Type:        "number",
                    Description: "Volatilité réalisée 20j maximale (annualisée). Ex: 0.4 pour 40%.",
                    Minimum:     &min0,
                    Maximum:     &max100,
                },
                "limit": {
                    Type:        "number",
                    Description: "Nombre maximum de résultats. Défaut: 10, maximum: 50.",
                    Minimum:     &min0,
                },
            },
            Required: []string{},
        },
    }
}

// Execute exécute l'outil et retourne un ToolResult
func (t *ScreenerTool) Execute(ctx context.Context, args map[string]interface{}) (mcp.ToolResult, error) {
    // Parsing des arguments avec valeurs par défaut
    sector, _    := args["sector"].(string)
    regime, _    := args["trend_regime"].(string)
    minADV       := getFloat(args, "min_adv_usd", 0)
    minPerf      := getFloat(args, "min_perf_1m_pct", -100)
    maxVol       := getFloat(args, "max_vol_20d", 999)
    limit        := int(getFloat(args, "limit", 10))

    if limit > 50 { limit = 50 }   // Sécurité : limiter les résultats

    // Construction de la requête SQL paramétrée (pas de string interpolation!)
    query := `
        SELECT
            symbol,
            company_name,
            sector,
            ROUND(close_price::NUMERIC, 2) AS close_price,
            ROUND(adv_20d_usd::NUMERIC / 1e6, 1) AS adv_20d_m,
            ROUND(perf_1m_pct::NUMERIC, 2) AS perf_1m_pct,
            ROUND(perf_3m_pct::NUMERIC, 2) AS perf_3m_pct,
            ROUND(realized_vol_20d::NUMERIC * 100, 1) AS vol_20d_pct,
            trend_regime,
            liquidity_class
        FROM gold_zone.mart_strategy_universe
        WHERE 1=1
          AND ($1::TEXT = '' OR sector = $1)
          AND ($2::TEXT = '' OR trend_regime = $2)
          AND adv_20d_usd >= $3
          AND perf_1m_pct >= $4
          AND realized_vol_20d <= $5
        ORDER BY perf_1m_pct DESC, adv_20d_usd DESC
        LIMIT $6
    `

    rows, err := t.db.Query(ctx, query, sector, regime, minADV, minPerf, maxVol, limit)
    if err != nil {
        return mcp.ToolResult{}, fmt.Errorf("database query failed: %w", err)
    }
    defer rows.Close()

    type Candidate struct {
        Symbol       string  `json:"symbol"`
        Name         string  `json:"name"`
        Sector       string  `json:"sector"`
        Price        float64 `json:"price_usd"`
        ADV_M        float64 `json:"adv_20d_million_usd"`
        Perf1M       float64 `json:"perf_1m_pct"`
        Perf3M       float64 `json:"perf_3m_pct"`
        Vol20D       float64 `json:"realized_vol_20d_pct"`
        TrendRegime  string  `json:"trend_regime"`
        Liquidity    string  `json:"liquidity_class"`
    }

    var candidates []Candidate
    for rows.Next() {
        var c Candidate
        if err := rows.Scan(&c.Symbol, &c.Name, &c.Sector, &c.Price, &c.ADV_M,
                             &c.Perf1M, &c.Perf3M, &c.Vol20D, &c.TrendRegime, &c.Liquidity); err != nil {
            continue
        }
        candidates = append(candidates, c)
    }

    result, _ := json.MarshalIndent(map[string]interface{}{
        "candidates": candidates,
        "count":      len(candidates),
        "filters_applied": map[string]interface{}{
            "sector": sector, "trend_regime": regime,
            "min_adv_usd": minADV, "min_perf_1m_pct": minPerf,
        },
    }, "", "  ")

    return mcp.ToolResult{
        Content: []mcp.ContentBlock{{Type: "text", Text: string(result)}},
    }, nil
}

func getFloat(args map[string]interface{}, key string, def float64) float64 {
    if v, ok := args[key]; ok {
        if f, ok := v.(float64); ok {
            return f
        }
    }
    return def
}

Détection de Régime de Marché

Détecter le Régime de Marché depuis le Gold Mart

Avant qu'un LLM puisse recommander des stratégies, il doit comprendre le contexte macro. Nous exposons une détection de régime en temps réel qui interroge le mart Gold agrégé — pas de calcul à la volée, réponse en <100ms.

package tools

import (
    "context"
    "encoding/json"
    "fmt"

    "github.com/jackc/pgx/v5/pgxpool"
    "securities-mcp/internal/mcp"
)

type MarketRegime struct {
    Regime           string  `json:"regime"`             // "Risk-On", "Risk-Off", "Transition"
    BullishPct       float64 `json:"bullish_pct"`        // % actions au-dessus SMA50
    GoldenCrossPct   float64 `json:"golden_cross_pct"`   // % avec Golden Cross
    AvgVol20D        float64 `json:"avg_realized_vol_pct"`
    MedianADV_B      float64 `json:"median_adv_billion"`
    Breadth          string  `json:"market_breadth"`     // "Expanding", "Narrowing", "Weak"
    TopSectors       []string `json:"top_sectors"`
    BottomSectors    []string `json:"bottom_sectors"`
    AsOfDate         string  `json:"as_of_date"`
}

func (t *RegimeTool) Execute(ctx context.Context, args map[string]interface{}) (mcp.ToolResult, error) {
    // Requête agrégée sur le Gold Mart — aucun calcul de fenêtre temps-réel
    row := t.db.QueryRow(ctx, `
        WITH universe AS (
            SELECT
                trend_regime,
                realized_vol_20d,
                adv_20d_usd,
                sector,
                perf_1m_pct
            FROM gold_zone.mart_strategy_universe
            WHERE instrument_type = 'EQUITY'
        ),
        regime_stats AS (
            SELECT
                COUNT(*) FILTER (WHERE trend_regime LIKE 'Bullish%')::FLOAT / COUNT(*) * 100
                    AS bullish_pct,
                COUNT(*) FILTER (WHERE trend_regime = 'Bullish — Golden Cross')::FLOAT / COUNT(*) * 100
                    AS golden_cross_pct,
                AVG(realized_vol_20d) * 100
                    AS avg_vol_20d_pct,
                PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY adv_20d_usd) / 1e9
                    AS median_adv_b
            FROM universe
        )
        SELECT
            bullish_pct, golden_cross_pct,
            avg_vol_20d_pct, median_adv_b,
            CURRENT_DATE::TEXT AS as_of_date
        FROM regime_stats
    `)

    var r MarketRegime
    r.AsOfDate = "unknown"
    if err := row.Scan(&r.BullishPct, &r.GoldenCrossPct, &r.AvgVol20D, &r.MedianADV_B, &r.AsOfDate); err != nil {
        return mcp.ToolResult{}, fmt.Errorf("regime query failed: %w", err)
    }

    // Détermination du régime par règles métier
    switch {
    case r.BullishPct >= 70 && r.GoldenCrossPct >= 40:
        r.Regime = "Risk-On — Strong Bull Market"
        r.Breadth = "Expanding"
    case r.BullishPct >= 55:
        r.Regime = "Risk-On — Moderate Uptrend"
        r.Breadth = "Expanding"
    case r.BullishPct >= 40:
        r.Regime = "Transition — Mixed Signals"
        r.Breadth = "Narrowing"
    case r.BullishPct >= 25:
        r.Regime = "Risk-Off — Early Bear"
        r.Breadth = "Weak"
    default:
        r.Regime = "Risk-Off — Bear Market"
        r.Breadth = "Weak"
    }

    // Top/Bottom secteurs
    sectorRows, _ := t.db.Query(ctx, `
        SELECT sector, sector_momentum_score
        FROM gold_zone.mart_sector_momentum
        WHERE instrument_type = 'EQUITY' AND sector IS NOT NULL
        ORDER BY momentum_rank ASC
        LIMIT 3
    `)
    defer sectorRows.Close()
    for sectorRows.Next() {

        }

Evidence.dev — BI-as-Code

Dashboards BI-as-Code avec Evidence.dev

Pendant que l'agent IA opère de façon autonome, les portfolio managers exigent une supervision humaine. Evidence.dev transforme du Markdown avec des requêtes SQL directement en dashboards interactifs. Tout est versionné avec le code — pas de Tableau, pas de Metabase, juste du Markdown + SQL + Git.

Qu'est-ce qu'Evidence.dev ?

Evidence.dev est un framework open-source qui génère des dashboards statiques à partir de fichiers Markdown contenant des blocs de requêtes SQL. Chaque fichier .md dans pages/ devient une page de dashboard. Les requêtes SQL s'exécutent contre votre PostgreSQL à la compilation, les résultats sont intégrés dans un site statique. Le dashboard final peut être hébergé sur GitHub Pages, Netlify, ou un serveur interne — sans serveur backend.

Gouvernance IA

Guardrails et Gouvernance du Serveur MCP

Exposer une base de données financière à un LLM sans guardrails est dangereux. Voici les couches de protection implémentées dans notre serveur MCP.

go — Middleware de sécurité MCP (rate limiting + audit log) 
// internal/mcp/middleware.go

// RateLimiter : evite que le LLM exécute trop de requêtes par minute
type RateLimiter struct {
    mu       sync.Mutex
    calls    map[string][]time.Time   // tool_name → timestamps
    limit    int                      // max appels par fenêtre
    window   time.Duration
}

func (rl *RateLimiter) Allow(toolName string) bool {
    rl.mu.Lock()
    defer rl.mu.Unlock()

    now := time.Now()
    // Purger les timestamps anciens
    var recent []time.Time
    for _, t := range rl.calls[toolName] {
        if now.Sub(t) < rl.window {
            recent = append(recent, t)
        }
    }
    if len(recent) >= rl.limit {
        return false   // Rate limit atteint
    }
    rl.calls[toolName] = append(recent, now)
    return true
}

Quiz : MCP & Interfaces IA

Quelle est la différence fondamentale entre un LLM qui génère du SQL directement et un LLM qui utilise MCP ?
Contrôle, sécurité, et prévisibilité. Un LLM générant du SQL arbitraire peut écrire des requêtes non optimisées (scans de table entière), accéder à des données sensibles (raw_zone), ou théoriquement générer des requêtes destructives (DROP, UPDATE). Avec MCP, le LLM appelle uniquement des outils prédéfinis avec des schémas stricts : paramètres validés, requêtes SQL paramétrées (pas d'injection), utilisateur PostgreSQL read-only, résultats limités. Le serveur MCP est une API contrôlée vers la base de données — le LLM ne "voit" jamais le SQL sous-jacent.
Pourquoi les requêtes SQL dans les outils MCP utilisent-elles des paramètres ($1, $2...) plutôt que de l'interpolation de chaînes ?
Pour prévenir les injections SQL (SQL Injection). Un LLM malicieux ou détourné (prompt injection) pourrait tenter de passer des valeurs comme ' OR 1=1 -- dans les arguments. Avec des requêtes paramétrées, PostgreSQL traite les paramètres comme des données et non comme du code SQL — l'injection devient impossible. C'est la même règle que pour tout code qui interagit avec une base de données : ne jamais construire des requêtes SQL par concatenation de chaînes avec des entrées utilisateurs (ou LLM).
Qu'est-ce que le "transport stdio" dans le Model Context Protocol ?
C'est le mécanisme de communication principal de MCP. Le client MCP (ex: Claude Desktop) lance le serveur MCP comme un processus enfant et communique via les flux stdin (entrée) et stdout (sortie) du processus. Les messages sont des objets JSON-RPC 2.0 délimités par des sauts de ligne. Avantages : pas de port réseau à gérer, pas de TLS à configurer, le serveur tourne localement sur la machine de l'utilisateur. Alternative : le transport SSE (Server-Sent Events) pour les serveurs MCP distants. Notre serveur Go utilise stdio, idéal pour une intégration desktop.
Pourquoi Evidence.dev peut-il héberger des dashboards sans backend, et quelles sont les limitations de cette approche ?
Evidence.dev génère un site statique à la compilation. Les requêtes SQL s'exécutent une seule fois lors du build (npm run build) — les résultats sont sérialisés en JSON dans les fichiers HTML/JS statiques. Le site résultant peut être hébergé sur n'importe quel CDN (GitHub Pages, Vercel, Netlify) sans backend. Limitations : les données ne sont "fraîches" qu'au moment du dernier build. Pour un dashboard mis à jour chaque nuit (après le pipeline dbt), on planifie le build Evidence.dev comme job Nomad périodique. Les données en temps réel (tick-by-tick) ne sont pas adaptées à cette approche.
Comment le rate limiting protège-t-il le Securities Master des appels excessifs d'un LLM ?
En limitant le nombre d'appels par outil par fenêtre temporelle. Un LLM en boucle (hallucination d'outil, prompt malicieux) pourrait appeler get_price_history des milliers de fois. Notre RateLimiter maintient un journal des timestamps des appels récents par outil. Si le nombre d'appels dans la fenêtre (ex: 60 secondes) dépasse le seuil (ex: 30 appels), le serveur retourne une erreur MCP standardisée (isError: true) sans exécuter la requête PostgreSQL. Combiné avec le pool de connexions pgxpool (max 10 connexions), cela protège la base de données des surcharges.
