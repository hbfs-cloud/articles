Architecture OMS

L'Adapter Pattern : Découpler l'IA des Brokers

Interactive Brokers (actions/options) et Binance (crypto) ont des APIs radicalement différentes : IB TWS utilise un protocole socket propriétaire ; Binance expose un REST API + WebSocket. Notre OMS implémente le pattern Adapter : une interface Go commune, deux implémentations concrètes.

go — internal/broker/interface.go (interface commune) 
package broker

import (
    "context"
    "time"
)

// BrokerAdapter est l'interface commune pour tous les brokers
// L'agent IA et le moteur de réconciliation n'utilisent QUE cette interface
// Ils sont complètement ignorants d'IB, Binance, ou tout autre broker
type BrokerAdapter interface {
    // Lecture de l'état live
    GetPositions(ctx context.Context) ([]Position, error)
    GetAccountValue(ctx context.Context) (AccountValue, error)
    GetOpenOrders(ctx context.Context) ([]Order, error)

    // Exécution d'ordres
    PlaceOrder(ctx context.Context, req OrderRequest) (Order, error)
    CancelOrder(ctx context.Context, orderID string) error
    CancelAllOrders(ctx context.Context) error

    // Streaming de données de marché (pour les prix live)
    SubscribeTicker(ctx context.Context, symbols []string) (<-chan TickData, error)

    // Info broker
    BrokerName() string
    IsConnected(ctx context.Context) bool
}

// Position représente une position live (indépendante du broker)
type Position struct {
    Symbol      string
    ISIN        string
    Quantity    float64   // négatif = short
    AvgPrice    float64
    MarketValue float64   // en devise du compte
    PnL         float64
    PnLPct      float64
    AsOf        time.Time
}

// OrderRequest est l'ordre généré par le moteur de réconciliation
type OrderRequest struct {
    Symbol    string
    Quantity  float64     // positif = achat, négatif = vente
    OrderType string      // "LIMIT", "MARKET", "MOC" (Market on Close)
    LimitPx   *float64    // nul si OrderType = "MARKET"
    TimeInForce string    // "DAY", "GTC", "IOC"
    Strategy  string     // tag pour l'audit log (ex: "momentum_breakout")
}

// AccountValue agrège la valeur du compte
type AccountValue struct {
    NetLiquidation float64
    BuyingPower    float64
    MarginUsed     float64
    Currency       string
}

// TickData est un prix de marché live streamé
type TickData struct {
    Symbol    string
    Bid       float64
    Ask       float64
    Last      float64
    Volume    int64
    Timestamp time.Time
}

Interactive Brokers

Adaptateur Interactive Brokers TWS

Interactive Brokers TWS (Trader Workstation) expose son API via un protocole socket sur localhost:7497 (paper trading) ou 7496 (live). La librairie Go officielle est ibapi — mais elle est complexe. Nous construisons un wrapper minimaliste.

go — internal/broker/ibkr.go (adaptateur IB) 
package broker

import (
    "context"
    "fmt"
    "sync"
    "time"

    ibapi "github.com/hadrienk/ibapi"
)

// IBKRAdapter implémente BrokerAdapter pour Interactive Brokers TWS
type IBKRAdapter struct {
    mu      sync.RWMutex
    client  *ibapi.EClient
    wrapper *IBWrapper   // Récepteur des callbacks asynchrones IB
    host    string
    port    int
    clientID int32
}

// IBWrapper implémente ibapi.EWrapper — reçoit toutes les réponses async d'IB
type IBWrapper struct {
    mu          sync.Mutex
    positions   map[string]*Position    // symbol → position live
    orders      map[int64]*Order        // orderID → ordre
    accountVal  AccountValue
    tickers     map[string]chan TickData
}

func NewIBKRAdapter(host string, port int, clientID int32) *IBKRAdapter {
    wrapper := &IBWrapper{
        positions: make(map[string]*Position),
        orders:    make(map[int64]*Order),
        tickers:   make(map[string]chan TickData),
    }
    client := ibapi.NewEClient(wrapper)
    return &IBKRAdapter{
        client:   client,
        wrapper:  wrapper,
        host:     host,
        port:     port,
        clientID: clientID,
    }
}

func (a *IBKRAdapter) Connect(ctx context.Context) error {
    if err := a.client.Connect(a.host, a.port, a.clientID); err != nil {
        return fmt.Errorf("IB TWS connection failed: %w", err)
    }
    // Démarrer la goroutine de lecture des messages IB
    go a.client.Run()

    // Attendre la confirmation de connexion (timeout 10s)
    select {
    case <-a.wrapper.Connected():
        return nil
    case <-time.After(10 * time.Second):
        return fmt.Errorf("IB TWS connection timeout after 10s")
    case <-ctx.Done():
        return ctx.Err()
    }
}

func (a *IBKRAdapter) GetPositions(ctx context.Context) ([]Position, error) {
    // Demander toutes les positions au TWS
    a.client.ReqPositions()

    // Attendre la réponse async (positions arrivées via wrapper.UpdatePortfolio)
    select {
    case <-a.wrapper.PositionsReady():
        a.mu.RLock()
        defer a.mu.RUnlock()
        positions := make([]Position, 0, len(a.wrapper.positions))
        for _, p := range a.wrapper.positions {
            positions = append(positions, *p)
        }
        return positions, nil
    case <-time.After(5 * time.Second):
        return nil, fmt.Errorf("timeout waiting for IB positions")
    case <-ctx.Done():
        return nil, ctx.Err()
    }
}

func (a *IBKRAdapter) PlaceOrder(ctx context.Context, req OrderRequest) (Order, error) {
    // Convertir un OrderRequest générique en ordre IB
    ibOrder := ibapi.Order{
        Action:      "BUY",
        TotalQuantity: req.Quantity,
        OrderType:   req.OrderType,
        Tif:         req.TimeInForce,
    }
    if req.Quantity < 0 {
        ibOrder.Action = "SELL"
        ibOrder.TotalQuantity = -req.Quantity
    }
    if req.LimitPx != nil {
        ibOrder.LmtPrice = *req.LimitPx
    }

    // Contrat IB pour l'action
    contract := ibapi.Contract{
        Symbol:   req.Symbol,
        SecType:  "STK",
        Exchange: "SMART",   // IB Smart Routing
        Currency: "USD",
    }

    orderID := a.client.NextOrderID()
    a.client.PlaceOrder(orderID, contract, ibOrder)

    return Order{
        ExternalID: fmt.Sprintf("IB-%d", orderID),
        Symbol:     req.Symbol,
        Quantity:   req.Quantity,
        Status:     "SUBMITTED",
        SubmittedAt: time.Now(),
    }, nil
}

func (a *IBKRAdapter) BrokerName() string { return "InteractiveBrokers-TWS" }
Binance

Adaptateur Binance (Crypto 24/7)

go — internal/broker/binance.go (adaptateur Binance REST + WebSocket) 
package broker

import (
    "context"
    "fmt"
    "net/http"
    "encoding/json"
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "time"
    "strconv"
)

// BinanceAdapter implémente BrokerAdapter pour Binance Spot
type BinanceAdapter struct {
    apiKey    string
    secretKey string
    baseURL   string     // "https://api.binance.com" ou "https://testnet.binance.vision"
    client    *http.Client
}

func NewBinanceAdapter(apiKey, secretKey string, testnet bool) *BinanceAdapter {
    base := "https://api.binance.com"
    if testnet {
        base = "https://testnet.binance.vision"
    }
    return &BinanceAdapter{
        apiKey:    apiKey,
        secretKey: secretKey,
        baseURL:   base,
        client:    &http.Client{Timeout: 5 * time.Second},
    }
}

// signParams ajoute timestamp + signature HMAC-SHA256 requise par Binance
func (a *BinanceAdapter) signParams(params string) string {
    ts := strconv.FormatInt(time.Now().UnixMilli(), 10)
    body := params + "×tamp=" + ts

    mac := hmac.New(sha256.New, []byte(a.secretKey))
    mac.Write([]byte(body))
    sig := hex.EncodeToString(mac.Sum(nil))

    return body + "&signature=" + sig
}

func (a *BinanceAdapter) PlaceOrder(ctx context.Context, req OrderRequest) (Order, error) {
    side := "BUY"
    qty := req.Quantity
    if req.Quantity < 0 {
        side = "SELL"
        qty = -req.Quantity
    }

    // Binance utilise BTCUSDT, ETHUSDT — pas BTC-USD
    // Normalisation du symbole (notre OMS utilise BTC-USD en interne)
    binanceSymbol := normalizeToBinanceSymbol(req.Symbol)

    params := fmt.Sprintf(
        "symbol=%s&side=%s&type=%s&quantity=%g&timeInForce=%s",
        binanceSymbol, side, req.OrderType, qty, req.TimeInForce,
    )
    if req.LimitPx != nil {
        params += fmt.Sprintf("&price=%.8f", *req.LimitPx)
    }
    params = a.signParams(params)

    httpReq, _ := http.NewRequestWithContext(ctx, "POST",
        a.baseURL+"/api/v3/order?"+params, nil)
    httpReq.Header.Set("X-MBX-APIKEY", a.apiKey)

    resp, err := a.client.Do(httpReq)
    if err != nil {
        return Order{}, fmt.Errorf("binance order failed: %w", err)
    }
    defer resp.Body.Close()

    var result struct {
        OrderID int64  `json:"orderId"`
        Status  string `json:"status"`
        Symbol  string `json:"symbol"`
    }
    if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
        return Order{}, fmt.Errorf("binance response decode: %w", err)
    }

    return Order{
        ExternalID:  fmt.Sprintf("BNB-%d", result.OrderID),
        Symbol:      req.Symbol,
        Quantity:    req.Quantity,
        Status:      result.Status,
        SubmittedAt: time.Now(),
    }, nil
}

// normalizeToBinanceSymbol : "BTC-USD" → "BTCUSDT", "ETH-USD" → "ETHUSDT"
func normalizeToBinanceSymbol(symbol string) string {
    mapping := map[string]string{
        "BTC-USD": "BTCUSDT", "ETH-USD": "ETHUSDT",
        "SOL-USD": "SOLUSDT", "BNB-USD": "BNBUSDT",
        "XRP-USD": "XRPUSDT",
    }
    if s, ok := mapping[symbol]; ok { return s }
    // Fallback : remplacer "-USD" par "USDT"
    return symbol[:len(symbol)-4] + "USDT"
}

func (a *BinanceAdapter) BrokerName() string { return "Binance-Spot" }
Réconciliation de Positions

Algorithme de Réconciliation Target vs. Live

Le cœur de l'OMS : comparer le portefeuille cible (généré par l'IA) au portefeuille live (lu via le broker adapter) et calculer les ordres minimum nécessaires pour converger vers la cible.

1
Lire le Cible
Charger l'allocation cible depuis PostgreSQL (strategies.target_portfolio).
2
Lire le Live
Appeler adapter.GetPositions() pour l'état réel du compte broker.
3
Calculer le Delta
Delta = Cible − Live pour chaque symbole. Positif → achat, Négatif → vente.
4
Filtrer les Micro-ordres
Ignorer les deltas < min_order_size ou < 1% de la position actuelle.
5
Valider le Risque
Chaque ordre passe par les garde-fous de risque avant soumission au broker.
6
Soumettre & Logger
PlaceOrder() + INSERT dans orders.order_events pour l'audit trail.
go — internal/oms/reconcile.go (moteur de réconciliation) 
package oms

import (
    "context"
    "fmt"
    "math"

    "securities-oms/internal/broker"
    "securities-oms/internal/db"
    "securities-oms/internal/risk"
)

// ReconciliationEngine réconcilie le portefeuille cible avec le live
type ReconciliationEngine struct {
    adapter  broker.BrokerAdapter
    store    *db.OrderStore
    risk     *risk.RiskController
    config   ReconcileConfig
}

type ReconcileConfig struct {
    MinOrderSizePct float64   // Ignorer si delta < X% de la position actuelle
    MinOrderSizeUSD float64   // Ignorer si delta < X$ de valeur notionnelle
    MaxOrderSizeUSD float64   // Limiter chaque ordre à X$ (éviter les gros impacts marché)
    LimitOrderSlip  float64   // Pct de slippage autorisé pour prix limit (ex: 0.002 = 0.2%)
}

type TargetAllocation struct {
    Symbol         string
    TargetPctNav   float64    // % du NAV alloué à ce titre
    StrategyTag    string
}

// Reconcile exécute un cycle complet de réconciliation
func (e *ReconciliationEngine) Reconcile(ctx context.Context, targets []TargetAllocation) error {
    // 1. Lire le NAV et les positions live
    acctVal, err := e.adapter.GetAccountValue(ctx)
    if err != nil {
        return fmt.Errorf("get account value: %w", err)
    }
    livePositions, err := e.adapter.GetPositions(ctx)
    if err != nil {
        return fmt.Errorf("get positions: %w", err)
    }

    // Index des positions live par symbole
    liveBySymbol := make(map[string]broker.Position)
    for _, p := range livePositions {
        liveBySymbol[p.Symbol] = p
    }

    // 2. Calculer les deltas
    for _, target := range targets {
        targetUSD := target.TargetPctNav * acctVal.NetLiquidation / 100.0

        livePos := liveBySymbol[target.Symbol]
        deltaUSD := targetUSD - livePos.MarketValue

        // 3. Filtrer les micro-deltas
        if math.Abs(deltaUSD) < e.config.MinOrderSizeUSD {
            continue
        }
        if livePos.MarketValue > 0 && math.Abs(deltaUSD)/livePos.MarketValue < e.config.MinOrderSizePct {
            continue
        }

        // 4. Calculer la quantité en nombre d'actions
        // Pour cela, on a besoin du prix live — streamé via SubscribeTicker
        // Simplifié ici : on utilise un prix mid approximatif
        midPrice := e.getMidPrice(ctx, target.Symbol)
        if midPrice <= 0 {
            continue
        }

        qty := deltaUSD / midPrice

        // Cap par taille max d'ordre
        if deltaUSD > e.config.MaxOrderSizeUSD {
            qty = e.config.MaxOrderSizeUSD / midPrice
        } else if deltaUSD < -e.config.MaxOrderSizeUSD {
            qty = -e.config.MaxOrderSizeUSD / midPrice
        }

        // 5. Valider les garde-fous de risque AVANT de soumettre
        orderReq := broker.OrderRequest{
            Symbol:      target.Symbol,
            Quantity:    qty,
            OrderType:   "LIMIT",
            TimeInForce: "DAY",
            Strategy:    target.StrategyTag,
        }
        // Prix limit = mid ± slippage autorisé
        limitPx := midPrice * (1 + e.config.LimitOrderSlip)
        if qty < 0 { limitPx = midPrice * (1 - e.config.LimitOrderSlip) }
        orderReq.LimitPx = &limitPx

        if err := e.risk.Validate(ctx, orderReq, acctVal); err != nil {
            // Garde-fou déclenché → log et skip, pas de panic
            e.store.LogRejection(ctx, orderReq, err.Error())
            continue
        }

        // 6. Soumettre l'ordre
        order, err := e.adapter.PlaceOrder(ctx, orderReq)
        if err != nil {
            e.store.LogError(ctx, orderReq, err.Error())
            continue
        }

        // Audit trail complet dans PostgreSQL
        e.store.InsertOrderEvent(ctx, order, "SUBMITTED")
    }
    return nil
}

func (e *ReconciliationEngine) getMidPrice(ctx context.Context, symbol string) float64 {
    // Implémentation : query Gold Mart pour le dernier close_price
    // En production : prix live depuis le stream WebSocket broker
    return e.store.GetLastClosePrice(ctx, symbol)
}
Contrôles de Risque

Guardrails de Risque Multi-Niveaux

Tout ordre passe par un RiskController avant d'atteindre le broker. Ces garde-fous sont indépendants de l'IA — ils ne peuvent pas être désactivés par un signal de l'agent.

📊
Position Limit
Max 10% NAV
Un seul titre ne peut dépasser 10% du capital. Stop-out automatique si dépassé.
🎯
Secteur Limit
Max 30% NAV
La concentration sectorielle est limitée pour éviter le risque idiosyncratique.
📉
Daily Loss Limit
Max -2% NAV/jour
Circuit breaker : stop de tous les ordres si le P&L journalier dépasse -2%.
⚡
Order Rate
Max 10 ordres/min
Rate limiter pour éviter de bombarder les APIs broker (risque de ban).
💰
Notional Limit
Max $50K/ordre
Aucun ordre individuel ne peut dépasser $50 000 de valeur notionnelle.
🚫
Blacklist
Liste statique
Instruments interdits (ex: pink sheets, warrants, certificats) non-tradeables.
go — internal/risk/controller.go (garde-fous de risque) 
package risk

import (
    "context"
    "fmt"
    "math"

    "securities-oms/internal/broker"
)

type RiskController struct {
    maxPositionPct  float64   // 0.10 = 10%
    maxSectorPct    float64   // 0.30 = 30%
    maxDailyLossPct float64   // 0.02 = 2%
    maxOrderUSD     float64   // 50000
    blacklist       map[string]bool
}

func NewRiskController() *RiskController {
    return &RiskController{
        maxPositionPct:  0.10,
        maxSectorPct:    0.30,
        maxDailyLossPct: 0.02,
        maxOrderUSD:     50000,
        blacklist:       loadBlacklist(),   // Depuis fichier de config ou DB
    }
}

// Validate vérifie tous les garde-fous pour un ordre donné
// Retourne une erreur décrivant quel guard a été déclenché, nil si OK
func (rc *RiskController) Validate(ctx context.Context, req broker.OrderRequest, acct broker.AccountValue) error {
    // Guard 1 : Blacklist
    if rc.blacklist[req.Symbol] {
        return fmt.Errorf("RISK_BLACKLIST: %s is on the trading blacklist", req.Symbol)
    }

    // Guard 2 : Notional limit par ordre
    notionalUSD := math.Abs(req.Quantity) * (*req.LimitPx)
    if notionalUSD > rc.maxOrderUSD {
        return fmt.Errorf("RISK_ORDER_TOO_LARGE: $%.0f > max $%.0f", notionalUSD, rc.maxOrderUSD)
    }

    // Guard 3 : Position limit (après exécution de cet ordre)
    currentExposure := rc.getCurrentExposure(ctx, req.Symbol)
    projectedExposure := currentExposure + notionalUSD
    projectedPct := projectedExposure / acct.NetLiquidation
    if projectedPct > rc.maxPositionPct {
        return fmt.Errorf("RISK_POSITION_LIMIT: %.1f%% > max %.1f%% for %s",
            projectedPct*100, rc.maxPositionPct*100, req.Symbol)
    }

    // Guard 4 : Daily loss circuit breaker
    dailyPnL := rc.getDailyPnL(ctx)
    dailyPnLPct := dailyPnL / acct.NetLiquidation
    if dailyPnLPct < -rc.maxDailyLossPct {
        return fmt.Errorf("RISK_DAILY_LOSS: Daily P&L %.2f%% exceeds limit %.2f%%",
            dailyPnLPct*100, -rc.maxDailyLossPct*100)
    }

    return nil   // Tous les garde-fous OK
}

-- Vue de monitoring : comparer la dernière réconciliation au NAV actuel
-- Exécuté toutes les heures par un job Nomad de monitoring

WITH latest_reconciliation AS (
    SELECT
        symbol,
        target_pct_nav,
        live_pct_nav,
        ABS(target_pct_nav - live_pct_nav) AS drift_pct,
        reconciled_at
    FROM ops.reconciliation_snapshots
    WHERE reconciled_at = (
        SELECT MAX(reconciled_at)
        FROM ops.reconciliation_snapshots
    )
),
summary AS (
    SELECT
        COUNT(*) AS num_positions,
        SUM(drift_pct) AS total_drift_pct,
        MAX(drift_pct) AS max_drift_pct,
        COUNT(*) FILTER (WHERE drift_pct > 1.0) AS num_breaches,
        MAX(reconciled_at) AS last_reconciled_at,
        NOW() - MAX(reconciled_at) AS age_since_last_recon
    FROM latest_reconciliation
)

SELECT
    *,
    CASE
        WHEN num_breaches > 0             THEN 'ALERT: Position drift > 1% NAV'
        WHEN age_since_last_recon > '2 hours' THEN 'ALERT: Stale reconciliation'
        WHEN total_drift_pct > 5          THEN 'WARN: High aggregate drift'
        ELSE 'OK'
    END AS health_status
FROM summary;

Quiz Final : OMS & Opérations

Pourquoi l'interface BrokerAdapter est-elle définie séparément des implémentations IBKR et Binance ?
Pour découpler le moteur métier (réconciliation, risk) des détails d'implémentation des APIs broker. Le ReconciliationEngine et le RiskController n'importent jamais le package ibkr ou binance — ils utilisent uniquement broker.BrokerAdapter. Cela permet : (1) d'ajouter un nouveau broker (ex: Interactive Brokers Europe, Alpaca) sans toucher au moteur de réconciliation ; (2) d'injecter un mock broker dans les tests unitaires ; (3) de tester le moteur de réconciliation en isolation avec des positions simulées. C'est le principe SOLID "Dependency Inversion".
Pourquoi normalise-t-on "BTC-USD" en "BTCUSDT" avant d'envoyer un ordre à Binance ?
Les brokers ont des conventions de nommage incompatibles. Notre Securities Master utilise une convention interne standardisée (BTC-USD, ETH-USD) alignée sur Yahoo Finance. Binance utilise la convention BTCUSDT, ETHUSDT (pas de tiret, suffixe "T" pour USDT). Si on envoie "BTC-USD" directement à l'API Binance, on obtient une erreur Invalid symbol. La normalisation est gérée dans l'adaptateur — le moteur de réconciliation utilise toujours la convention interne et ignore les particularités de chaque broker.
Expliquez pourquoi les contrôles de risque sont séparés de l'agent IA et ne peuvent pas être désactivés par un signal LLM.
Séparation des préoccupations (Separation of Concerns) et défense en profondeur. L'agent IA peut faire des erreurs : hallucinations, mauvaise compréhension d'un contexte de marché, prompt injection d'un acteur malveillant. Si le LLM pouvait désactiver les contrôles de risque, un bug ou une attaque pourrait causer des pertes catastrophiques. Le RiskController est un système purement déterministe, codé en dur en Go, qui ne prend aucune instruction d'un LLM. Il valide chaque ordre indépendamment selon des règles métier claires. C'est la même approche qu'un circuit breaker électrique — il ne demande pas permission avant de couper le courant.
Qu'est-ce qu'un SLO (Service Level Objective) et en quoi diffère-t-il d'un SLA ?
Un SLO est un objectif interne de qualité de service ; un SLA est un engagement contractuel externe. SLO = "notre pipeline dbt doit s'exécuter en moins de 45 minutes" — c'est une cible d'équipe, mesurée en interne, sans pénalité contractuelle si elle est manquée. SLA = "nous garantissons à nos clients que les données seront disponibles avant 9h00 ou remboursement" — engagement légal avec des pénalités financières. En pratique : définissez d'abord des SLOs stricts en interne, avec alertes automatiques (Prometheus AlertManager, PagerDuty). Si vous tenez vos SLOs, vous pouvez garantir des SLAs à vos clients avec une marge de sécurité.
Comment le "Daily Loss Limit" (circuit breaker) protège-t-il contre les marchés en forte chute ?
En stoppant automatiquement toute exécution d'ordres si le P&L journalier dépasse un seuil. Si le marché chute brutalement (ex: -5% en une heure), un algorithme de momentum sans circuit breaker peut continuer d'acheter en croyant être face à un pullback, amplifiant les pertes. Avec un Daily Loss Limit de -2% NAV, dès que les pertes atteignent ce seuil, le RiskController rejette tous les nouveaux ordres d'achat et permet uniquement la réduction des positions existantes. L'équipe reçoit une alerte P1 et peut décider manuellement de reprendre ou de liquider. C'est la protection contre le "runaway loss" le plus basique de tout OMS institutionnel.
