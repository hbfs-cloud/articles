QueryData — The Swiss Army Knife

QueryData is the most-used tool because it supports 58 different data types through a single interface. The AI specifies which data types it needs, and the server fetches all of them in parallel.

QueryData Call Example 
// Claude calls QueryData to get everything about NVDA
{
  "types": "quote,bars_daily,financials,earnings_quarterly,holders,stats,support_resistance,volume_profile,sentiment_overall,trading_signals,analyst_actions,insider_transactions,news",
  "symbols": "NVDA"
}

// Returns a unified JSON with all 13 data types
// Each type is keyed by its name:
{
  "quote": { "price": 142.50, "change": 3.2, ... },
  "bars_daily": [{ "date": "2026-03-05", "close": 142.50, ... }],
  "financials": { "revenue": 130.5e9, ... },
  "sentiment_overall": { "score": 0.72, "label": "bullish" },
  ...
}

Design Insight: One Tool vs Many

We debated between 58 individual tools (get_quote, get_bars, get_financials...) and one unified QueryData tool. We chose the unified approach because: (1) Claude can request multiple data types in one call, reducing round-trips. (2) The server parallelizes all fetches internally. (3) 58 tools would overwhelm the model's tool selection. The tradeoff: the types parameter is a comma-separated string, which is slightly less discoverable than individual tools.

// Manual commands
articles analyse NVDA         // Generate ticker analysis

The bot translates Discord commands into claude -p "command" executions in a tmux session. Claude Code reads the project's CLAUDE.md (which contains all the article generation instructions), calls MCP tools for data, generates the HTML, runs the indexing script, and git pushes.

Hard-Won Wisdom

Lessons Learned — What Works, What Doesn't

What Works Brilliantly

  • Structured data in, structured article out. When MCP tools return clean JSON, Claude produces consistent, high-quality articles every time.
  • CLAUDE.md as the instruction manual. Detailed instructions in the project's CLAUDE.md file act as the "brain" — the AI follows them reliably for 50+ section templates.
  • Reference articles. Telling Claude "read this existing article and match the format" produces better results than describing the format abstractly.
  • Git as deployment. git push triggers GitHub Pages deployment — no CI/CD configuration needed.
  • ECharts for every chart. Claude is remarkably good at generating ECharts configurations from raw data.

Anti-Hallucination Strategies

The biggest risk with AI-generated financial content is hallucinated data. Here's how we prevent it:

Data-Only Sources

Every number comes from MCP tools. Never ask Claude to "estimate" or "recall" a stock price.

Price Spot Validation

Scanner verifies entry prices against live quotes. >10% deviation = rejected.

Cross-Validation

LLMAnalysis tool sends data to a second AI (DeepSeek) for independent verification.

Retrospectives

Weekly retros score past predictions. Consistently wrong patterns are pruned.

Size Checks

Articles under 10KB are rejected (truncated). Expected range: 50-120KB.

Disclaimers

Every article includes mandatory financial disclaimers with explicit "not financial advice" language.

What Doesn't Work

  • Asking Claude to "remember" market data. It will confidently cite wrong prices from training data. Always fetch live data via MCP.
  • Too many tools at once. When we had 25+ tools, Claude would sometimes pick the wrong one. We consolidated into QueryData with types.
  • Inline CSS everywhere. Articles initially had thousands of inline styles. Migration script cleaned 433 articles to use shared CSS classes.
  • No validation post-generation. Early articles sometimes had broken HTML, missing sections, or wrong dates. Adding size checks and section counters fixed this.

Final Quiz

Series Capstone Quiz

Why did DailyTickers use one QueryData tool instead of 58 individual tools?
Three reasons: (1) Fewer round-trips — Claude can request 13 data types in one call instead of 13 separate calls. (2) Internal parallelization — the server fetches all types simultaneously. (3) Tool selection clarity — 58 tools would overwhelm the AI's ability to pick the right one; a single unified tool with a types parameter is more reliable.
What's the #1 anti-hallucination strategy for AI-generated financial content?
Never let the AI cite data from memory. Every number, price, percentage, and date must come from a live data source (MCP tool call or web search). Claude's training data contains market information, but it's outdated and often wrong. The rule: if it's a number, it must come from a tool.
Describe the complete pipeline from Discord command to published article.
(1) Discord bot receives scheduled command. (2) Bot executes claude -p "command" in tmux. (3) Claude Code reads CLAUDE.md for instructions. (4) Claude calls MCP tools (GetMarketOverview, QueryData) + web searches. (5) Claude generates 50-100KB HTML article. (6) add_card.js indexes the article. (7) git add + git commit + git push. (8) GitHub Pages deploys in ~60 seconds.
What makes CLAUDE.md files so powerful for AI automation?
CLAUDE.md files encode domain expertise as structured instructions. They tell the AI exactly what data to fetch, what sections to write, what format to use, what conventions to follow, and what validation checks to run. They're the equivalent of an employee handbook — they turn a general-purpose AI into a domain specialist. The more detailed and specific the instructions, the more consistent and reliable the output.
If you wanted to build a similar system for a different domain (e.g., legal research), what would you need?
You'd need: (1) An MCP server with tools for your domain's data sources (legal databases, case law APIs, court filings). (2) A CLAUDE.md file encoding the domain expertise (citation formats, legal terminology, document structure). (3) Reference documents showing the expected output format. (4) Validation pipelines (citation checking, factual verification). (5) A scheduling system (Discord bot, cron, or CI/CD) for automated workflows. The MCP + CLAUDE.md pattern is domain-agnostic.
