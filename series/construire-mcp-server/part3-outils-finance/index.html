Architecture providers : sources de données interchangeables

Un serveur MCP finance sérieux ne dépend jamais d'une seule source de données. Yahoo Finance peut être limité en rate, SEC EDGAR peut être lent, et un provider premium (Polygon, IEX) peut changer ses tarifs. La solution : une couche d'abstraction provider qui rend les sources interchangeables.

# providers/base.py — Interface commune
from abc import ABC, abstractmethod
from typing import Optional

class MarketDataProvider(ABC):
    """Interface commune pour toutes les sources de données marché."""

    @abstractmethod
    async def get_quote(self, ticker: str) -> dict:
        """Prix actuel, change%, volume, market cap."""

    @abstractmethod
    async def get_bars(self, ticker: str, period: str = "1y") -> list[dict]:
        """OHLCV historique."""

    @abstractmethod
    async def get_fundamentals(self, ticker: str) -> dict:
        """P/E, EV/EBITDA, margins, etc."""

    @abstractmethod
    async def get_earnings(self, ticker: str) -> list[dict]:
        """Résultats trimestriels (EPS actual vs estimate)."""

Yahoo Finance

Gratuit, large couverture. Prix, fondamentaux, options, earnings. Rate limited (~2000/h).

SEC EDGAR

Filings officiels (10-K, 10-Q, S-3). Gratuit, pas de rate limit agressif. Données brutes à parser.

FRED

Données macro (taux, inflation, GDP). API clé gratuite. Parfait pour les indicateurs macro.

Binance

Crypto en temps réel. API publique sans clé. WebSocket pour le streaming.

# providers/yahoo.py — Implémentation Yahoo Finance
import httpx

class YahooProvider(MarketDataProvider):
    BASE = "https://query1.finance.yahoo.com/v8/finance"

    def __init__(self):
        self.client = httpx.AsyncClient(
            timeout=10.0,
            headers={"User-Agent": "MCP-Finance/1.0"}
        )

    async def get_quote(self, ticker: str) -> dict:
        url = f"{self.BASE}/chart/{ticker}?interval=1d&range=1d"
        resp = await self.client.get(url)
        data = resp.json()
        result = data["chart"]["result"][0]
        meta = result["meta"]

        return {
            "ticker": ticker.upper(),
            "price": meta["regularMarketPrice"],
            "previous_close": meta["previousClose"],
            "change_pct": round(
                (meta["regularMarketPrice"] / meta["previousClose"] - 1) * 100, 2
            ),
            "volume": meta.get("regularMarketVolume", 0),
            "market_cap": meta.get("marketCap"),
            "currency": meta.get("currency", "USD"),
            "exchange": meta.get("exchangeName"),
            "source": "yahoo_finance",
            "as_of": meta.get("regularMarketTime")
        }

Un provider = une responsabilité

Chaque provider gère sa propre connexion HTTP, son parsing, et ses particularités. Le code qui appelle le provider ne sait pas (et n'a pas besoin de savoir) si les données viennent de Yahoo, Polygon, ou d'un fichier CSV local. Cette abstraction est ce qui vous permet de changer de source sans toucher à un seul outil MCP.

QueryData est l'outil le plus appelé du serveur. Plutôt que d'avoir un outil par type de donnée (GetQuote, GetTechnicals, GetFundamentals...), on expose un point d'entrée unique avec un paramètre types qui spécifie ce qu'on veut :

async def handle_query_data(provider, arguments: dict) -> dict:
    ticker = arguments["ticker"]
    types = arguments["types"]
    period = arguments.get("period", "1y")
    result = {"ticker": ticker.upper()}

    if "quote" in types:
        result["quote"] = await provider.get_quote(ticker)

    if "bars_daily" in types:
        bars = await provider.get_bars(ticker, period)
        result["bars_daily"] = bars[-30:]  # Limiter à 30 jours pour le contexte
        result["bars_count"] = len(bars)

    if "technicals" in types:
        bars = await provider.get_bars(ticker, period)
        result["technicals"] = calculate_technicals(bars)

    if "fundamentals" in types:
        result["fundamentals"] = await provider.get_fundamentals(ticker)

    if "earnings" in types:
        result["earnings"] = await provider.get_earnings(ticker)

    return result

Limiter les bars retournées

Un an de données OHLCV = ~252 lignes × 6 colonnes = ~1500 valeurs. C'est beaucoup de tokens pour le contexte du LLM. Retournez les 30 derniers jours par défaut et le nombre total de barres disponibles. Le LLM saura qu'il y a plus de données disponibles sans les injecter toutes dans son contexte.

Section 3

Calculer les indicateurs techniques

Plutôt que de dépendre d'une API externe pour les indicateurs, on les calcule côté serveur à partir des barres OHLCV. Ça nous donne le contrôle total et réduit les dépendances.

RSI — Relative Strength Index

Formule RSI
RSI = 100 − (100 / (1 + RS))   où RS = avg_gain / avg_loss 
def calculate_rsi(closes: list[float], period: int = 14) -> float:
    """RSI de Wilder — moyenne exponentielle des gains/pertes."""
    if len(closes) < period + 1:
        return 50.0  # Pas assez de données

    deltas = [closes[i] - closes[i-1] for i in range(1, len(closes))]
    gains = [d if d > 0 else 0 for d in deltas]
    losses = [-d if d < 0 else 0 for d in deltas]

    # Première moyenne = simple
    avg_gain = sum(gains[:period]) / period
    avg_loss = sum(losses[:period]) / period

    # Ensuite = exponentielle (Wilder)
    for i in range(period, len(gains)):
        avg_gain = (avg_gain * (period - 1) + gains[i]) / period
        avg_loss = (avg_loss * (period - 1) + losses[i]) / period

    if avg_loss == 0:
        return 100.0
    rs = avg_gain / avg_loss
    return round(100 - (100 / (1 + rs)), 2)

EMA — Exponential Moving Average

def calculate_ema(values: list[float], period: int) -> list[float]:
    """EMA avec multiplier = 2/(period+1)."""
    if len(values) < period:
        return []
    multiplier = 2 / (period + 1)
    ema = [sum(values[:period]) / period]  # SMA comme seed
    for v in values[period:]:
        ema.append(v * multiplier + ema[-1] * (1 - multiplier))
    return ema

def calculate_technicals(bars: list[dict]) -> dict:

Pourquoi calculer côté serveur ?

Trois raisons : 1) Pas de dépendance à un service de calcul externe (un point de défaillance en moins). 2) Contrôle sur les paramètres — notre RSI utilise la méthode Wilder exacte, pas une approximation. 3) Cohérence — les mêmes paramètres RSI(14), EMA(20/50/200) partout dans le système.

Un JSON plat est plus efficace en tokens (pas de niveaux d'accolades répétés) et plus facile à interpréter pour le LLM. Un JSON avec {"valuation": {"pe": {"trailing": 28.4, "forward": 24.1}}} consomme plus de tokens pour la structure que pour les données. Avec "pe_trailing": 28.4, "pe_forward": 24.1, chaque token porte de l'information utile.

RunScreener : le DSL de filtrage

Le screening est la fonctionnalité qui rend un MCP finance vraiment puissant. Le LLM peut formuler des critères complexes en langage naturel, et votre outil les traduit en filtres :

SCREENER_TOOL = Tool(
    name="RunScreener",
    description="""Screen the US stock universe with custom filters.
Filters use a simple DSL: 'field operator value [AND field operator value]...'

Available fields:
- price, volume, market_cap, sector, industry
- rsi_14, ema_20_slope, distance_from_52w_high_pct
- pe_trailing, pe_forward, ev_ebitda, ps_ratio
- gross_margin_pct, net_margin_pct, roe_pct
- revenue_growth_yoy_pct, debt_to_equity

Operators: >, <, >=, <=, =, !=, BETWEEN, IN

Examples:
- 'rsi_14 < 30 AND volume > 1000000 AND market_cap > 2000000000'
- 'sector IN (Technology, Healthcare) AND pe_forward < 20'
- 'distance_from_52w_high_pct BETWEEN -15 AND -5'

Returns top 50 matches sorted by match score.""",
    inputSchema={

Parser le DSL

import re

def parse_filter(expression: str) -> list[dict]:
    """Parse 'rsi_14 < 30 AND volume > 1M' → liste de conditions."""
    conditions = []
    parts = re.split(r'\s+AND\s+', expression, flags=re.IGNORECASE)

    for part in parts:
        # Handle BETWEEN
        m = re.match(r'(\w+)\s+BETWEEN\s+(.+?)\s+AND\s+(.+)', part, re.I)
        if m:
            conditions.append({
                "field": m.group(1),
                "op": "between",
                "low": parse_value(m.group(2)),
                "high": parse_value(m.group(3))
            })
            continue

        # Handle IN
        m = re.match(r'(\w+)\s+IN\s+\((.+?)\)', part, re.I)
        if m:
            values = [v.strip().strip("'") for v in m.group(2).split(",")]
            conditions.append({"field": m.group(1), "op": "in", "values": values})
            continue

        # Handle comparison operators
        m = re.match(r'(\w+)\s*(>=|<=|!=|>|<|=)\s*(.+)', part)
        if m:
            conditions.append({
                "field": m.group(1),
                "op": m.group(2),
                "value": parse_value(m.group(3).strip())
            })

    return conditions

Gotcha : abs() non supporté

Si le LLM envoie abs(distance_from_52w_high_pct) < 10, le parser échouera. Les fonctions comme abs() ne font pas partie du DSL. Documentez cette limitation dans la description de l'outil et proposez l'alternative : distance_from_52w_high_pct BETWEEN -10 AND 10.

La puissance du « zéro paramètre »

Un outil sans paramètre est un pattern puissant. Le LLM peut l'appeler sans hésiter (pas de choix de paramètres à faire). Il sert de point de départ contextuel : le LLM obtient une vue d'ensemble, puis affine avec des appels ciblés (QueryData pour un ticker spécifique). C'est comme arriver au bureau et regarder d'abord l'écran Bloomberg — vue macro → drill-down.

Section 7

Gestion d'erreurs : ne jamais mentir

La règle #1 d'un serveur MCP finance : ne jamais retourner de données fausses. Si Yahoo est down, on dit « Yahoo est down ». On n'invente pas un prix.

async def call_tool(name: str, arguments: dict) -> CallToolResult:
    try:
        if name == "QueryData":
            result = await handle_query_data(provider, arguments)
            return CallToolResult(
                content=[TextContent(type="text", text=json.dumps(result))]
            )
    except httpx.TimeoutException:
        # Source de données timeout — le dire clairement
        return CallToolResult(
            content=[TextContent(
                type="text",
                text=json.dumps({
                    "error": "data_source_timeout",
                    "message": "Yahoo Finance did not respond within 10s",
                    "suggestion": "Try again in a few seconds or use a different ticker"
                })
            )],
            isError=True
        )
    except KeyError as e:
        # Ticker non trouvé
        return CallToolResult(
            content=[TextContent(
                type="text",
                text=json.dumps({
                    "error": "ticker_not_found",
                    "message": f"No data found for ticker '{arguments.get('ticker')}'",
                    "suggestion": "Check the ticker symbol — use AAPL, not Apple"
                })
            )],
            isError=True
        )

Ce qu'on retient

  • Provider pattern — une interface commune, des implémentations interchangeables (Yahoo, Polygon, Binance)
  • QueryData — point d'entrée unique avec types[] plutôt que N outils séparés
  • Techniques côté serveur — RSI, EMA, MACD calculés localement pour contrôle et indépendance
  • JSON plat — suffixes _pct, _b, noms descriptifs, pas de nesting
  • Screener DSL — mini-langage parsable que le LLM peut formuler naturellement
  • MarketOverview — zéro paramètre, point de départ contextuel pour tout briefing
  • Pas de mensonge — erreur = dire l'erreur, jamais inventer de données
